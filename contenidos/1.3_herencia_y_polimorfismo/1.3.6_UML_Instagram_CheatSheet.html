Reglas de Dominio e Invariantes por Clase

1. Reglas de Publicacion (Padre)

• Invariante de Likes: El contador nunca puede ser negativo. darLike() incrementa en 1.

• Autor Obligatorio: No se permiten autores vacíos o nulos (longitud > 2 caracteres).

• ID Inmutable: El identificador único se asigna al construir el objeto y no tiene setter público.

2. Reglas de Historia (Hijo)

• Vigencia Temporal: Nace activa con duración de 24 hrs. Al llamar a caducar(), estaActiva = false.

• Visualización Restringida: Si esMejoresAmigos == true, solo usuarios autorizados pueden acceder al contenido.

• Métricas: Cada llamada a registrarVista() incrementa el contador de vistas si la historia está activa.

3. Reglas de Reel (Hijo)

• Rango de Duración: Mínimo 3 segundos, máximo 90 segundos. Si se ingresa un valor fuera de rango, se ajusta al límite más cercano o se rechaza.

• Audio por defecto: Si el nombre del audio viene vacío, se asigna "Audio original de " + autor.

• Reproducción: reproducir() simula la reproducción y suma +1 a reproducciones.

4. Reglas de Post Tradicional (Hijo)

• Límite de Texto: El pieDeFoto tiene un límite máximo de 2200 caracteres.

• Comentarios: Si comentariosHabilitados == false, el detalle debe indicar explícitamente "Comentarios desactivados".

• Ubicación Opcional: Si no se define ubicación, se almacena como "Sin ubicación".

Diseño del Menú Interactivo de Consola

El programa de consola se construye siguiendo el patrón estructurado: Scanner + Variable de control (while) + Switch por opciones + Colección polimórfica (ArrayList<Publicacion>).

Opción 1 Crear Publicación (Submenú por tipo)

Despliega un submenú para elegir qué tipo de publicación instanciar: 1) Historia, 2) Reel o 3) Post. Solicita los datos comunes al padre (autor) y luego los atributos específicos del hijo (duración, audio, pie de foto, etc.). Instancia el objeto correspondiente y lo agrega a la lista polimórfica: publicaciones.add(nuevaPub);

Opción 2 Listar Feed Completo (Polimorfismo en acción)

Recorre la colección completa con un loop for-each de tipo padre for (Publicacion p : publicaciones). Ejecuta p.mostrarDetalle(). Gracias a la ligadura dinámica (Polimorfismo), cada publicación imprime su formato personalizado sin necesidad de if-else por tipo.

Opción 3 Interactuar con una Publicación (Dar Like / Reproducir)

Pide al usuario el id o índice de la publicación. Busca el objeto en la lista y le aplica la operación p.darLike(). Si es un Reel, permite adicionalmente llamar a su método específico de reproducción.

Opción 4 Filtrar Publicaciones por Tipo

Permite al usuario ver únicamente Historias activas, solo Reels o solo Posts tradicionales, verificando la instancia mediante instanceof o métodos de estado.

Opción 5 Salir del Sistema

Cambia la bandera booleana de control del ciclo mantenerMenu = false;, imprime un mensaje de despedida y cierra los recursos.

Esqueleto de Implementación Java (Main.java)

import java.util.ArrayList;
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        ArrayList<Publicacion> feed = new ArrayList<>();
        boolean ejecutando = true;

        while (ejecutando) {
            System.out.println("\n=== INSTAGRAM CONSOLE APP ===");
            System.out.println("1. Crear publicación");
            System.out.println("2. Ver Feed completo (Polimorfismo)");
            System.out.println("3. Dar Like a una publicación");
            System.out.println("4. Salir");
            System.out.print("Seleccione una opción: ");

            String opcion = scanner.nextLine().trim();

            switch (opcion) {
                case "1":
                    crearPublicacion(scanner, feed);
                    break;
                case "2":
                    mostrarFeed(feed);
                    break;
                case "3":
                    darLikePublicacion(scanner, feed);
                    break;
                case "4":
                    System.out.println("¡Hasta pronto! 🛸");
                    ejecutando = false;
                    break;
                default:
                    System.out.println("Opción no válida. Intente nuevamente.");
                    break;
            }
        }
    }

    private static void mostrarFeed(ArrayList<Publicacion> feed) {
        if (feed.isEmpty()) {
            System.out.println("El feed está vacío. ¡Crea una publicación primero!");
            return;
        }
        System.out.println("\n--- FEED DE PUBLICACIONES ---");
        // POLIMORFISMO: Una sola llamada a método padre ejecuta la versión del hijo correspondiente
        for (Publicacion pub : feed) {
            pub.mostrarDetalle();
            System.out.println("---------------------------");
        }
    }
}

Scanner & Primitivos en Consola

⚠️ El Problema Clásico del Salto de Línea en Scanner

Cuando utilizas scanner.nextInt() o scanner.nextDouble(), Java lee el número pero deja el carácter de salto de línea (\n) pendiente en el buffer. Al hacer inmediatamente después un scanner.nextLine(), este consume ese \n residual y se salta la lectura.

❌ Enfoque Problemático 
System.out.print("Edad: ");
int edad = scanner.nextInt(); // Deja \n en buffer

System.out.print("Nombre: ");
String nombre = scanner.nextLine(); 
// ¡ERROR! Lee el \n y queda vacío ""
✅ Enfoque Recomendado (Profe Carlitos) 
System.out.print("Edad: ");
// Leer siempre como línea de texto completa y parsear
int edad = Integer.parseInt(scanner.nextLine());

System.out.print("Nombre: ");
String nombre = scanner.nextLine(); 
// ¡Funciona perfecto siempre!
📖

Métodos Clave de java.util.Scanner

Método Retorno Uso y Comportamiento
scanner.nextLine() String Lee toda la línea hasta presionar Enter. Limpia el buffer por completo. (Recomendado)
scanner.next() String Lee únicamente la siguiente palabra (hasta encontrar un espacio o salto de línea).
scanner.hasNextLine() boolean Verifica si existe otra línea disponible para leer en el flujo de entrada.

Cheat Sheet Maestro: Conceptos Fundamentales de Java OOP

1 Paradigma Orientado a Objetos (POO)

Forma de diseñar software modelando el dominio del problema como un conjunto de objetos interactivos que poseen estado (atributos) y comportamiento (métodos), protegiendo sus propias reglas en lugar de tener funciones globales que manipulen datos sueltos.

2 Clases y Abstracción

• Abstracción: Seleccionar únicamente los atributos y operaciones relevantes para el sistema, ignorando los detalles innecesarios.
• Clase: El molde o plano de diseño que define la estructura.
• Objeto (Instancia): La entidad concreta creada en memoria con la palabra clave new. 

Personaje p1 = new Personaje("Steve", 100); // p1 es la instancia concreta

3 Métodos (Anatomía, this y Sobrecarga)

Un bloque de código que ejecuta una acción específica del objeto.
• Firma del Método: Nombre + tipos de parámetros.
• Palabra clave this: Referencia a la instancia actual del objeto que ejecuta el código.
• Sobrecarga (Overload): Mismo nombre de método en la misma clase con distintos parámetros. 

public void setVida(int vida) {
    this.vida = (vida < 0) ? 0 : vida; // this.vida es el atributo, vida es el parámetro
}

4 Encapsulamiento & Modificadores de Acceso

Ocultar el estado interno de un objeto para evitar modificaciones directas no autorizadas o inválidas. Se logra declarando atributos private y exponiendo getters y setters con validaciones (manteniendo las invariantes).

Modificador Misma Clase Mismo Paquete Clases Hijas (Subclases) Mundo Exterior
private ✓ Sí ✗ No ✗ No ✗ No
(default / package) ✓ Sí ✓ Sí ✗ No ✗ No
protected ✓ Sí ✓ Sí ✓ Sí ✗ No
public ✓ Sí ✓ Sí ✓ Sí ✓ Sí

5 Herencia (extends y super)

Mecanismo que permite a una clase hija heredar atributos y métodos de una clase padre, promoviendo la reutilización de código y la creación de jerarquías lógicas (relación "es-un"). 

public class Zombie extends Character {
    public Zombie(String nombre) {
        super(nombre, 80); // Llama al constructor de Character
    }
}

6 Polimorfismo & @Override

Capacidad de tratar objetos de diferentes clases hijas a través de una referencia de tipo padre, ejecutando la versión especializada del método en tiempo de ejecución (ligadura dinámica). 

Character c = new Zombie(); // Variable de tipo Padre, Objeto tipo Hijo
c.atacar(); // Ejecuta Zombie.atacar(), NO Character.atacar()

7 Clases Abstractas vs Interfaces

Característica Clase Abstracta (abstract class) Interfaz (interface)
Propósito Base común para clases estrechamente emparentadas con estado compartido. Contrato de comportamiento que cualquier clase puede cumplir (capacidad).
Instanciación No se puede instanciar directamente con new. No se puede instanciar directamente con new.
Herencia múltiple No (Java solo permite heredar de 1 sola clase: extends). Sí (Una clase puede implementar múltiples interfaces: implements).
Atributos Puede tener atributos de instancia de cualquier tipo y visibilidad. Solo constantes (public static final).

8 Manejo de Excepciones (try-catch-finally)

Estructura para capturar y controlar errores en tiempo de ejecución sin que el programa colapse abruptamente. 

try {
    System.out.print("Ingrese número: ");
    int opcion = Integer.parseInt(scanner.nextLine());
} catch (NumberFormatException e) {
    System.out.println("Error: Debe ingresar un número entero válido.");
} finally {
    // Código que se ejecuta SIEMPRE (haya o no excepción)
}

9 Colecciones (ArrayList<T>)

Estructuras de datos dinámicas que crecen y se reducen automáticamente en memoria según se añadan o eliminen elementos. 

ArrayList<Publicacion> lista = new ArrayList<>();

lista.add(new Historia("H1", "carlos")); // Agregar elemento
Publicacion p = lista.get(0);            // Obtener por índice
int total = lista.size();                // Cantidad de elementos
lista.remove(0);                         // Eliminar por índice o referencia
boolean vacia = lista.isEmpty();         // Verificar si está vacía
