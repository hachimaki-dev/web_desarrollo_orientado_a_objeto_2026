Polimorfismo

Un mismo mensaje, comportamientos diferentes según el objeto que lo recibe.

01 · Contexto

¿Dónde estamos?

Ya trabajamos con herencia: una clase hija extiende a una clase padre y hereda sus atributos y métodos.

Lo que ya sabemos

extends permite que una clase hija herede de una clase padre.

Lo que falta

¿Qué pasa cuando la clase hija necesita hacer lo mismo, pero de manera diferente?

02 · Repaso rápido

Herencia: lo esencial

La clase hija hereda todo lo public y protected del padre. No necesita reescribirlo.

public class Animal {
    private String nombre;

    public String getNombre() {
        return nombre;
    }

    public void hablar() {
        System.out.println("...");
    }
}

public class Perro extends Animal {
    // Perro ya tiene getNombre() y hablar()
    // heredados de Animal
}

Perro hereda getNombre() y hablar() sin escribir nada.

03 · El problema

Todos hablan igual

Si Perro, Gato y Pato heredan de Animal, los tres ejecutan el mismo hablar().

Animal perro = new Perro();
Animal gato  = new Gato();
Animal pato  = new Pato();

perro.hablar();  // "..."
gato.hablar();   // "..."
pato.hablar();   // "..."

Problema: en el mundo real, un perro ladra, un gato maúlla y un pato grazna. Necesitamos que cada uno haga lo suyo.

04 · Definición

Polimorfismo

Del griego: poly (muchas) + morphé (formas).

En programación orientada a objetos: un mismo método puede comportarse de forma diferente según la clase del objeto que lo ejecuta.

El método tiene el mismo nombre y la misma firma, pero cada clase hija define su propia versión.

Java decide en tiempo de ejecución cuál versión usar, basándose en el tipo real del objeto.

05 · @Override

Sobreescribir un método heredado

La clase hija puede redefinir un método del padre. Para indicarlo, usamos la anotación @Override.

public class Perro extends Animal {

    @Override
    public void hablar() {
        System.out.println("Guau guau");
    }
}
¿Qué hace @Override?

Le dice al compilador: "estoy redefiniendo un método que ya existe en el padre". Si el método no existe en el padre, el compilador marca error.

¿Es obligatorio?

Técnicamente no. Pero siempre hay que usarlo. Protege de errores de tipeo y hace el código más claro.

06 · Ejemplo completo

Cada animal habla a su manera

public class Animal {
    public void hablar() {
        System.out.println("...");
    }
}

public class Perro extends Animal {
    @Override
    public void hablar() {
        System.out.println("Guau guau");
    }
}

public class Gato extends Animal {
    @Override
    public void hablar() {
        System.out.println("Miau");
    }
}

public class Pato extends Animal {
    @Override
    public void hablar() {
        System.out.println("Cuac cuac");
    }
}
07 · Ejecución

¿Qué método se ejecuta?

Animal a1 = new Perro();
Animal a2 = new Gato();
Animal a3 = new Pato();

a1.hablar();  // → "Guau guau"
a2.hablar();  // → "Miau"
a3.hablar();  // → "Cuac cuac"

La variable es de tipo Animal, pero el objeto real es Perro, Gato o Pato. Java ejecuta el método de la clase real del objeto, no el de la variable.

Esto es polimorfismo: el mismo código (a.hablar()) produce resultados diferentes según el objeto.

08 · Jerarquía

Diagrama de clases

La clase padre define el contrato (el método existe). Cada clase hija define su implementación.

Animal
hablar() → "..."
▼ extends
Perro
hablar() → "Guau"
Gato
hablar() → "Miau"
Pato
hablar() → "Cuac"

El tipo de la variable determina qué métodos puedes llamar. El tipo del objeto determina cuál versión se ejecuta.

16 · Concepto clave

Variable de tipo padre, objeto de tipo hijo

Esta es la base del polimorfismo. Es lo que permite tratar objetos diferentes de forma uniforme.

Sin polimorfismo

Zombie z = new Zombie();
Dragon d = new Dragon();
Creeper c = new Creeper();

// Necesitas saber el tipo exacto
z.atacar();
d.atacar();
c.atacar();
vs

Con polimorfismo

Character[] mobs = {
    new Zombie(),
    new Dragon(),
    new Creeper()
};

// Un solo loop sirve para todos
for (Character m : mobs) {
    m.atacar();
}

Con polimorfismo, puedes agregar nuevos tipos sin cambiar el código que los usa.

17 · Reglas

Reglas para sobreescribir correctamente

Misma firma

El método hijo debe tener exactamente el mismo nombre, mismos parámetros y mismo tipo de retorno que el padre.

Mismo o mayor acceso

Si el padre dice public, el hijo no puede decir private. Puede mantener o ampliar el acceso, nunca restringirlo.

@Override siempre

Aunque no es obligatorio, úsalo siempre. Si escribes mal el nombre del método, el compilador te avisará.

No se aplica a static

Los métodos static pertenecen a la clase, no al objeto. No participan en polimorfismo.

18 · Error frecuente

Cambiar la firma del método

Si la firma no coincide exactamente, no es un override — es un método nuevo.

// En Animal:
public void hablar() { ... }

// En Perro (ERROR: parámetro extra):
@Override
public void hablar(String idioma) {   // ✗ Esto NO compila
    System.out.println("Guau");
}

El compilador marca error porque hablar(String) no existe en Animal. La anotación @Override te protegió de este error silencioso.

19 · Error frecuente

Olvidar @Override (y escribir mal el nombre)

// En Animal:
public void hablar() { ... }

// En Perro (sin @Override):
public void Hablar() {   // ← Mayúscula en "H"
    System.out.println("Guau");
}

// Esto compila sin error. Pero hablar() sigue
// ejecutando la versión del padre.
// Hablar() es un método NUEVO, no una sobreescritura.

Sin @Override, Java no sabe que querías sobreescribir. El error pasa desapercibido y el polimorfismo no funciona.

20 · super

Llamar al método del padre desde el hijo

A veces la clase hija quiere hacer lo que hace el padre, y además agregar algo propio. Para eso se usa super.

public class Dragon extends Character {

    @Override
    public String atacar() {
        String ataqueBase = super.atacar();
        return ataqueBase + " y además lanza fuego";
    }
}

super.atacar() ejecuta la versión del padre. El hijo puede usar ese resultado y extenderlo.

21 · Caso real: toString()

Un override que usarán siempre

Todas las clases en Java heredan de Object. Object tiene un método toString() que retorna algo como Character@1a2b3c.

public class Character {
    private String name;
    private int hit_points;

    @Override
    public String toString() {
        return name + " (HP: " + hit_points + ")";
    }
}

// Ahora:
Character c = new Character();
System.out.println(c);
// → "Steve (HP: 100)" en vez de "Character@1a2b3c"

toString() es probablemente el override más común en Java. Lo van a usar en casi todas las clases que creen.

22 · Resumen

Mapa conceptual

Herencia

La clase hija recibe atributos y métodos del padre (extends).

Override

La clase hija redefine un método heredado (@Override).

Polimorfismo

El mismo método produce comportamientos diferentes según el objeto real.

Variable tipo padre

Animal a = new Perro() permite tratar objetos diferentes de forma uniforme.

super

Permite llamar al método del padre desde el hijo para extenderlo.

toString()

Override de Object para definir cómo se muestra un objeto como texto.

23 · Mirada de diseño

¿Por qué importa el polimorfismo?

Polimorfismo permite escribir código que trabaja con el tipo padre, sin importar cuántos tipos hijos existan o se creen después.

Sin polimorfismo: cada vez que agregas un nuevo tipo de mob, debes modificar el código que los usa (agregar un if o un case para el tipo nuevo).

Con polimorfismo: el código que usa Character no necesita cambiar. El nuevo mob solo necesita implementar sus propios métodos.

Esto se conecta con un principio de diseño llamado Open/Closed: abierto para extensión, cerrado para modificación.
