Herencia y Polimorfismo

Guía paso a paso para implementar polimorfismo en el proyecto de tu sección.

1
Identifica tu jerarquía de clases

Abre tu proyecto. Deberías tener estos archivos:

  • Character.java — clase padre
  • Zombie.java — extiende Character
  • Dragon.java — extiende Character
  • Creeper.java — extiende Character
  • Enderman.java — extiende Character

Verifica que cada clase hija tiene extends Character en su declaración.

// Ejemplo: Zombie.java
public class Zombie extends Character {
    boolean canInffectVillager = true;
}

Abre tu proyecto. Deberías tener estos archivos:

  • Personaje.java — clase padre
  • Hacker.java — extiende Personaje
  • Programador.java — extiende Personaje
  • GameDev.java — extiende Personaje

Verifica que cada clase hija tiene extends Personaje en su declaración.

// Ejemplo: Hacker.java
public class Hacker extends Personaje {
    int inteligencia;
}

Pregunta de reflexión: ¿Qué atributos y métodos heredan las clases hijas del padre? Haz una lista mental antes de continuar.

2
Agrega un método al padre

El padre necesita un método que las clases hijas puedan sobreescribir. Este método define el "contrato": todas las clases hijas tendrán este comportamiento, pero cada una lo implementará a su manera.

Abre Character.java y agrega el método atacar():

// En Character.java, agrega este método:
public String atacar() {
    return "El personaje realiza un ataque básico";
}

Este es el comportamiento por defecto. Si una clase hija no sobreescribe atacar(), usará esta versión.

Abre Personaje.java y agrega el método trabajar():

// En Personaje.java, agrega este método:
public String trabajar() {
    return "El personaje realiza una tarea general";
}

Este es el comportamiento por defecto. Si una clase hija no sobreescribe trabajar(), usará esta versión.

Pregunta: ¿Por qué el método retorna un String en vez de hacer System.out.println directamente? Piensa en quién debería decidir cuándo y cómo mostrar la información.

3
Sobreescribe el método en cada clase hija

Ahora cada clase hija define su propia versión del método. Usa @Override para indicar que estás redefiniendo un método heredado.

Agrega atacar() con @Override en cada clase hija:

// Zombie.java
public class Zombie extends Character {
    boolean canInffectVillager = true;

    @Override
    public String atacar() {
        return "Zombie muerde e infecta";
    }
}

// Dragon.java
public class Dragon extends Character {
    boolean endCrystalCanHeal = true;

    @Override
    public String atacar() {
        return "Dragon lanza una bola de fuego";
    }
}

// Creeper.java
public class Creeper extends Character {
    boolean isWeakToCat = true;

    @Override
    public String atacar() {
        return "Creeper explota causando daño en area";
    }
}

// Enderman.java
public class Enderman extends Character {
    boolean isWeakToWater = true;

    @Override
    public String atacar() {
        return "Enderman se teletransporta y golpea";
    }
}

Agrega trabajar() con @Override en cada clase hija:

// Hacker.java
public class Hacker extends Personaje {
    int inteligencia;

    @Override
    public String trabajar() {
        return "Hacker analiza vulnerabilidades del sistema";
    }
}

// Programador.java
public class Programador extends Personaje {
    int lenguajes_dominados;

    @Override
    public String trabajar() {
        return "Programador escribe codigo limpio y eficiente";
    }
}

// GameDev.java
public class GameDev extends Personaje {
    int inspiracion;

    @Override
    public String trabajar() {
        return "GameDev diseña mecanicas de juego";
    }
}

Recuerda: la firma del método debe ser exactamente igual a la del padre: mismo nombre, mismos parámetros, mismo tipo de retorno. @Override te protege si cometes un error.

4
Prueba el polimorfismo

Ahora viene lo importante: probar que Java ejecuta la versión correcta del método según el tipo real del objeto.

En Main.java, crea objetos usando la variable de tipo padre:

// En Main.java, dentro de main o en un método de prueba:
Character mob1 = new Zombie();
Character mob2 = new Dragon();
Character mob3 = new Creeper();
Character mob4 = new Enderman();

System.out.println(mob1.atacar());
System.out.println(mob2.atacar());
System.out.println(mob3.atacar());
System.out.println(mob4.atacar());

Resultado esperado:

Zombie muerde e infecta
Dragon lanza una bola de fuego
Creeper explota causando daño en area
Enderman se teletransporta y golpea

En Main.java, crea objetos usando la variable de tipo padre:

// En Main.java, dentro de main o en un método de prueba:
Personaje p1 = new Hacker();
Personaje p2 = new Programador();
Personaje p3 = new GameDev();

System.out.println(p1.trabajar());
System.out.println(p2.trabajar());
System.out.println(p3.trabajar());

Resultado esperado:

Hacker analiza vulnerabilidades del sistema
Programador escribe codigo limpio y eficiente
GameDev diseña mecanicas de juego

Pregunta clave: La variable mob1p1 es de tipo CharacterPersonaje, pero el objeto real es un ZombieHacker. ¿Cuál versión del método se ejecuta? ¿La del padre o la del hijo? ¿Por qué?

5
Verifica con un array

El verdadero poder del polimorfismo se ve cuando tratas múltiples objetos diferentes con un solo loop.

// Crea un array de tipo Character con objetos de distintos tipos
Character[] mobs = {
    new Zombie(),
    new Dragon(),
    new Creeper(),
    new Enderman()
};

// Un solo loop para todos
for (Character mob : mobs) {
    System.out.println(mob.atacar());
}
// Crea un array de tipo Personaje con objetos de distintos tipos
Personaje[] equipo = {
    new Hacker(),
    new Programador(),
    new GameDev()
};

// Un solo loop para todos
for (Personaje p : equipo) {
    System.out.println(p.trabajar());
}

Piensa: Si mañana agregas una nueva clase hija (por ejemplo, SkeletonDBA), ¿necesitas cambiar el loop? ¿Por qué sí o por qué no?

6
Agrega toString()

Sobreescribe toString() en la clase padre para que cuando imprimas un objeto, muestre información útil en vez de la referencia de memoria.

// En Character.java
@Override
public String toString() {
    return mostrarNombre() + " | HP: " + mostrarVida() + " | MP: " + mostrarPM();
}

Prueba:

Character z = new Zombie();
z.validarNombre("Steve");
z.asignarVida(100);
System.out.println(z);
// → "STEVE | HP: 100 | MP: 0"
// En Personaje.java
@Override
public String toString() {
    return mostrarNombre() + " | HP: " + getVida() + " | Vivo: " + esta_vivo;
}

Prueba:

Personaje h = new Hacker();
h.validarNombre("Neo");
h.setVida(80);
System.out.println(h);
// → "NEO | HP: 80 | Vivo: true"
