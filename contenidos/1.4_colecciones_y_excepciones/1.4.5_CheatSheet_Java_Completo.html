Scanner y Entrada de Datos

Configuración básica

import java.util.Scanner;

Scanner scanner = new Scanner(System.in);

// Leer texto
System.out.print("Nombre: ");
String nombre = scanner.nextLine();

// Leer número (enfoque recomendado)
System.out.print("Edad: ");
int edad = Integer.parseInt(scanner.nextLine());

// Leer decimal
System.out.print("Precio: ");
double precio = Double.parseDouble(scanner.nextLine());

// Leer booleano
System.out.print("¿Activo? (true/false): ");
boolean activo = Boolean.parseBoolean(scanner.nextLine());

El problema del salto de línea

Enfoque problemático 
int edad = scanner.nextInt(); // Deja \n
String nombre = scanner.nextLine();
// Lee el \n residual → queda vacío ""
Enfoque recomendado 
int edad = Integer.parseInt(scanner.nextLine());
String nombre = scanner.nextLine();
// Funciona perfectamente

Casteo y Conversión de Tipos

Casting implícito (Widening)

De un tipo menor a uno mayor. Java lo hace automáticamente. No hay pérdida de datos.

int entero = 42;
double decimal = entero;  // int → double automáticamente
System.out.println(decimal); // 42.0

// Orden de widening:
// byte → short → int → long → float → double

Casting explícito (Narrowing)

De un tipo mayor a uno menor. Requiere paréntesis con el tipo destino. Puede haber pérdida de datos.

double decimal = 9.99;
int entero = (int) decimal;  // Trunca la parte decimal
System.out.println(entero);  // 9 (no redondea, trunca)

long grande = 1234567890L;
int normal = (int) grande;   // Cuidado con el rango

Conversión de tipos de objetos (POO)

// Upcasting (implícito) — hijo → padre
Publicacion pub = new Historia("H1", "carlos", true);
// Historia "sube" a Publicacion. Siempre seguro.

// Downcasting (explícito) — padre → hijo
if (pub instanceof Historia) {
    Historia h = (Historia) pub;  // Cast explícito
    h.registrarVista();           // Ahora accedes a métodos de Historia
}
// Siempre verificar con instanceof antes del downcasting

Estructuras de Repetición

while

Repite mientras la condición sea true. Evalúa la condición antes de cada iteración.

boolean ejecutando = true;
while (ejecutando) {
    // Mostrar menú, leer opción...
    if (opcion.equals("salir")) {
        ejecutando = false;
    }
}

do-while

Igual que while, pero ejecuta el bloque al menos una vez antes de evaluar la condición.

String respuesta;
do {
    System.out.print("¿Desea continuar? (si/no): ");
    respuesta = scanner.nextLine();
} while (respuesta.equals("si"));

for (contador)

Para cuando sabes cuántas veces repetir.

// Estructura: for (inicio; condición; incremento)
for (int i = 0; i < 5; i++) {
    System.out.println("Iteración: " + i); // 0, 1, 2, 3, 4
}

// Recorrer un ArrayList por índice
for (int i = 0; i < feed.size(); i++) {
    System.out.println(i + ". " + feed.get(i).getId());
}

for-each (enhanced for)

Para recorrer colecciones sin manejar índices.

// Estructura: for (Tipo variable : coleccion)
for (Publicacion pub : feed) {
    pub.mostrarDetalle();
}

// Equivalente con for tradicional:
for (int i = 0; i < feed.size(); i++) {
    feed.get(i).mostrarDetalle();
}

break y continue

// break: sale del bucle inmediatamente
for (Publicacion pub : feed) {
    if (pub.getId().equals("R1")) {
        System.out.println("Encontrado");
        break; // Deja de buscar
    }
}

// continue: salta a la siguiente iteración
for (Publicacion pub : feed) {
    if (!pub.isEstaActiva()) {
        continue; // Salta las inactivas
    }
    pub.mostrarDetalle(); // Solo muestra las activas
}

Los 4 Pilares de la POO

1 Abstracción

Seleccionar solo los atributos y operaciones relevantes para el sistema, ignorando detalles innecesarios.

// De todas las características de una publicación de Instagram,
// abstraemos solo las relevantes para nuestro sistema:
public class Publicacion {
    private String id;           // Identificador único
    private String autor;        // Quién publicó
    private String fechaCreacion;
    private int likes;           // Contador de likes
    protected boolean estaActiva;

    // Constructor, getters, métodos...
}

2 Encapsulamiento

Ocultar el estado interno con private y exponer acceso controlado con getters/setters que validan.

ModificadorMisma ClaseMismo PaqueteSubclasesMundo
private✓✗✗✗
(default)✓✓✗✗
protected✓✓✓✗
public✓✓✓✓
 
private int likes; // No se puede acceder directamente desde fuera

public void darLike() {
    this.likes++; // Validado: solo incrementa, nunca se puede poner negativo
}

public int getLikes() {
    return this.likes; // Solo lectura
}

3 Herencia (extends + super)

Una clase hija hereda atributos y métodos de una clase padre. Relación "es-un".

public class Historia extends Publicacion {
    private int duracionHoras = 24;
    private boolean esMejoresAmigos;
    private int vistas;

    public Historia(String id, String autor, boolean mejoresAmigos) {
        super(id, autor); // Llama al constructor del padre
        this.esMejoresAmigos = mejoresAmigos;
    }
}

// Historia ES UNA Publicacion
// Historia hereda: id, autor, likes, darLike(), etc.

4 Polimorfismo (@Override)

Un mismo método produce comportamientos diferentes según el objeto que lo ejecuta. El tipo de la variable determina qué métodos puedes llamar; el tipo del objeto determina cuál versión se ejecuta.

// La clase hija redefine el método del padre
public class Reel extends Publicacion {
    @Override
    public void mostrarDetalle() {
        System.out.println("[REEL] " + getAutor());
        System.out.println("Duración: " + duracionSegundos + "s");
        System.out.println("Audio: " + audioNombre);
    }
}

// Polimorfismo en acción:
Publicacion pub = new Reel("R1", "ana", 60, "Audio Viral");
pub.mostrarDetalle(); // Ejecuta la versión de Reel, no de Publicacion

// Con colecciones:
ArrayList<Publicacion> feed = new ArrayList<>();
for (Publicacion p : feed) {
    p.mostrarDetalle(); // Cada objeto ejecuta SU versión
}

Manejo de Excepciones

Estructura try-catch-finally

try {
    // Código que podría fallar
    int numero = Integer.parseInt(scanner.nextLine());
    System.out.println("Número: " + numero);

} catch (NumberFormatException e) {
    // Se ejecuta SOLO si ocurre esa excepción
    System.out.println("Error: no es un número válido.");

} finally {
    // Se ejecuta SIEMPRE (opcional)
    System.out.println("Fin del intento.");
}
// El programa continúa aquí

try {
    int i = Integer.parseInt(scanner.nextLine());
    Publicacion pub = feed.get(i);
    pub.mostrarDetalle();
} catch (NumberFormatException e) {
    System.out.println("Error: debe ingresar un número.");
} catch (IndexOutOfBoundsException e) {
    System.out.println("Error: índice fuera de rango.");
}
// Regla: las excepciones más específicas van PRIMERO

Patrón: Pedir dato hasta que sea válido

public static int pedirEntero(Scanner scanner, String mensaje) {
    while (true) {
        try {
            System.out.print(mensaje);
            return Integer.parseInt(scanner.nextLine());
        } catch (NumberFormatException e) {
            System.out.println("Error: debe ingresar un número entero.");
        }
    }
}

Patrón: Menú defensivo

while (ejecutando) {
    try {
        // Mostrar opciones...
        String opcion = scanner.nextLine().trim();
        switch (opcion) {
            case "1": /* acción */ break;
            case "2": /* acción */ break;
            default: System.out.println("Opción no válida.");
        }
    } catch (Exception e) {
        System.out.println("Error: " + e.getMessage());
    }
}
// El menú NUNCA se rompe ante entradas inválidas

Buenas prácticas

Sí hacer

Capturar excepciones específicas.

Dar mensajes claros al usuario.

Combinar if + try-catch.

Extraer validación a métodos auxiliares.

No hacer

Dejar bloques catch vacíos.

Capturar Exception genérico primero.

Usar excepciones para flujo normal.

Ignorar o suprimir errores.
