Excepciones

Cómo evitar que tu programa se rompa cuando algo sale mal.

🛸
Concepto

¿Qué es una excepción?

Un evento inesperado que ocurre durante la ejecución del programa y que interrumpe el flujo normal.

Ejemplos de errores comunes

El usuario escribe "abc" cuando se pide un número.

Se intenta acceder a la posición 10 de una lista con 3 elementos.

Se llama a un método sobre una variable que es null.

Sin manejo de excepciones

El programa se detiene abruptamente.

El usuario ve un mensaje de error críptico.

Se pierden datos no guardados.

Objetivo: Anticipar los errores y manejarlos de forma controlada, sin que el programa deje de funcionar.
El problema

¿Qué pasa sin try-catch?

import java.util.Scanner;

public class SinManejoError {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        System.out.print("Ingrese su edad: ");
        int edad = Integer.parseInt(scanner.nextLine()); // ← Si escribe "abc"...
        System.out.println("Tienes " + edad + " años");
    }
}

Si el usuario escribe "abc":

Exception in thread "main" java.lang.NumberFormatException:
    For input string: "abc"
        at java.base/java.lang.NumberFormatException...
        at java.base/java.lang.Integer.parseInt...

El programa se detiene. La línea System.out.println nunca se ejecuta.

Estructura

Anatomía de try-catch

try {
    // Código que PODRÍA fallar
    int edad = Integer.parseInt(scanner.nextLine());
    System.out.println("Edad: " + edad);

} catch (NumberFormatException e) {
    // Se ejecuta SOLO si ocurre ese error
    System.out.println("Error: debe ingresar un número válido.");
}
// El programa CONTINÚA normalmente aquí
1
Java intenta ejecutar el código dentro de try
2
Si ocurre la excepción indicada, salta al bloque catch
3
El programa continúa después del try-catch, sin detenerse
Bloque finally

finally — Se ejecuta siempre

El bloque finally se ejecuta haya o no excepción. Es opcional.

try {
    int numero = Integer.parseInt(scanner.nextLine());
    System.out.println("Número: " + numero);
} catch (NumberFormatException e) {
    System.out.println("Error: entrada no válida.");
} finally {
    System.out.println("Este mensaje SIEMPRE aparece.");
}
Si no hay excepción:

Se ejecuta try completo + finally

Si hay excepción:

Se ejecuta try hasta el error + catch + finally

Ejemplo genérico

Validar entrada numérica con Scanner

import java.util.Scanner;

public class EntradaSegura {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        int numero = 0;
        boolean valido = false;

        while (!valido) {
            try {
                System.out.print("Ingrese un número entero: ");
                numero = Integer.parseInt(scanner.nextLine());
                valido = true; // Solo llega aquí si no hubo excepción
            } catch (NumberFormatException e) {
                System.out.println("Error: eso no es un número. Intente de nuevo.");
            }
        }

        System.out.println("Número ingresado: " + numero);
    }
}

Patrón: while + try-catch = pedir el dato hasta que sea válido.

Jerarquía

Árbol de excepciones en Java

Throwable
Error
Errores graves del sistema (OutOfMemoryError). No se manejan.
Exception
RuntimeException
Errores de programación. No requieren declaración.
Checked Exceptions
Errores esperables. El compilador obliga a manejarlas.
En este curso trabajamos con RuntimeException y sus subclases, que son las más comunes en programas de consola.
Referencia

Excepciones más comunes

NumberFormatException

Al convertir un texto que no es número.

Integer.parseInt("abc"); // Error
IndexOutOfBoundsException

Al acceder a un índice fuera de rango de una lista o array.

lista.get(10); // Solo tiene 3 elementos
NullPointerException

Al llamar un método sobre una referencia null.

String s = null;
s.length(); // Error
ArithmeticException

Al dividir un entero por cero.

int x = 10 / 0; // Error
Múltiples catch

Capturar diferentes tipos de excepción

Puedes tener varios bloques catch para manejar diferentes errores de formas distintas.

try {
    System.out.print("Índice: ");
    int indice = Integer.parseInt(scanner.nextLine());
    Publicacion pub = feed.get(indice);
    pub.mostrarDetalle();

} catch (NumberFormatException e) {
    System.out.println("Error: debe ingresar un número.");

} catch (IndexOutOfBoundsException e) {
    System.out.println("Error: índice fuera de rango. Rango válido: 0 a " + (feed.size()-1));
}

Regla: Los catch se evalúan en orden. Siempre coloca las excepciones más específicas primero. Si pones Exception primero, las demás nunca se ejecutarán.

Patrón clave

Menú defensivo — El menú que nunca se rompe

Scanner scanner = new Scanner(System.in);
ArrayList<Publicacion> feed = new ArrayList<>();
boolean ejecutando = true;

while (ejecutando) {
    System.out.println("\n=== INSTAGRAM CONSOLE APP ===");
    System.out.println("1. Crear publicación");
    System.out.println("2. Ver Feed");
    System.out.println("3. Dar Like");
    System.out.println("4. Salir");

    try {
        System.out.print("Opción: ");
        String opcion = scanner.nextLine().trim();

        switch (opcion) {
            case "1": /* crear */ break;
            case "2": /* listar */ break;
            case "3": /* dar like */ break;
            case "4": ejecutando = false; break;
            default:
                System.out.println("Opción no válida.");
        }
    } catch (Exception e) {
        System.out.println("Error inesperado: " + e.getMessage());
    }
}
Patrón reutilizable

Pedir dato hasta que sea válido

// Método auxiliar reutilizable
public static int pedirEntero(Scanner scanner, String mensaje) {
    while (true) {
        try {
            System.out.print(mensaje);
            return Integer.parseInt(scanner.nextLine());
        } catch (NumberFormatException e) {
            System.out.println("Error: debe ingresar un número entero.");
        }
    }
}

// Uso en cualquier parte del programa:
int duracion = pedirEntero(scanner, "Duración del reel (seg): ");
int indice = pedirEntero(scanner, "Índice de la publicación: ");

Extraer la validación a un método auxiliar evita repetir el mismo try-catch en muchos lugares del código.

Colecciones + Excepciones

Errores comunes al trabajar con listas

ArrayList<Publicacion> feed = new ArrayList<>();

try {

Enfoque frágil 
// Asumir que el índice es válido
Publicacion pub = feed.get(indice);
pub.darLike();
vs
Enfoque defensivo 
// Verificar antes de acceder
if (indice >= 0 && indice < feed.size()) {
    feed.get(indice).darLike();

    System.out.println("Índice no válido.");
}
Buenas prácticas

Reglas para el manejo de excepciones

1. Sé específico en el catch

Captura NumberFormatException, no Exception. Así sabes exactamente qué error ocurrió.

2. No uses excepciones para flujo normal

Si puedes verificar con un if antes (ej: isEmpty()), hazlo. Las excepciones son para situaciones imprevistas.

3. Mensajes claros al usuario

En vez de "Exception caught", escribe "Error: debe ingresar un número entre 3 y 90."

4. No dejes catch vacíos

Un catch sin código oculta errores silenciosamente. Siempre informa o registra lo que pasó.

Diseño

Validación preventiva vs reactiva

Preventiva (con if) 
// Verificar ANTES de actuar
if (!feed.isEmpty()) {
    feed.get(0).mostrarDetalle();
} else {
    System.out.println("Feed vacío.");
}

Usar cuando la condición se puede verificar sin costo.

vs
Reactiva (con try-catch) 
// Intentar y manejar si falla
try {
    int n = Integer.parseInt(texto);
} catch (NumberFormatException e) {
    System.out.println("No es número.");
}

Usar cuando no hay forma simple de verificar antes (ej: parseo).

Regla general: Si puedes prevenir con un if, previene. Si no, usa try-catch. En la práctica, muchos programas combinan ambas estrategias.
Ejemplo completo

Dar Like con validación completa

private static void darLike(Scanner scanner, ArrayList<Publicacion> feed) {
    if (feed.isEmpty()) {
        System.out.println("El feed está vacío.");
        return;  // Validación preventiva
    }

    // Mostrar opciones
    for (int i = 0; i < feed.size(); i++) {
        System.out.println(i + ". " + feed.get(i).getId());
    }

    try {
        System.out.print("Índice de la publicación: ");
        int indice = Integer.parseInt(scanner.nextLine());

        if (indice < 0 || indice >= feed.size()) {
            System.out.println("Índice fuera de rango.");
            return;  // Validación preventiva
        }

        feed.get(indice).darLike();
        System.out.println("Like registrado. Total: " + feed.get(indice).getLikes());

    } catch (NumberFormatException e) {
        System.out.println("Error: debe ingresar un número.");
        // Validación reactiva
    }
}
Resumen

Lo que aprendimos

try-catch-finally

Estructura para capturar errores sin detener el programa. finally se ejecuta siempre.

Excepciones comunes

NumberFormatException, IndexOutOfBoundsException, NullPointerException, ArithmeticException.

Menú defensivo

while + try-catch + switch = un menú que nunca se rompe ante entradas inválidas.

Buenas prácticas

Ser específico, combinar if con try-catch, mensajes claros, nunca catch vacío.

Un buen programa no es el que nunca falla — es el que maneja las fallas de forma controlada y amigable para el usuario.
