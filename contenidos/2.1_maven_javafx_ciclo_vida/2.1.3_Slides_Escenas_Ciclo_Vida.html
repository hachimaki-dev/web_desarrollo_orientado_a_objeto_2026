Escenas y Ciclo de Vida

Stage, Scene, layouts, eventos y persistencia básica.

🛸
Conceptos clave

Stage vs. Scene

JavaFX separa la ventana del contenido. Esto permite cambiar lo que se muestra sin cerrar la ventana.

Stage (ventana)
Scene (contenido)
Label, Button, TextField...
Stage = la ventana

El marco, la barra de título, los botones de minimizar/cerrar.

Solo hay un Stage principal (lo recibe start()).

Puedes cambiar su título, tamaño, e ícono.

Scene = el contenido

Todo lo que hay dentro de la ventana: controles, layouts, estilos.

Puedes cambiar la Scene del Stage sin cerrar la ventana.

Cada Scene tiene un nodo raíz (root) que contiene todo.

Analogía: El Stage es un televisor. La Scene es el canal que estás viendo. Puedes cambiar de canal sin apagar la tele.

Ciclo de vida

Ciclo de vida de Application

Cuando ejecutas una app JavaFX, el framework llama a tres métodos en orden:

init()
→
start(Stage)
→
La app corre...
→
stop()
MétodoCuándo se ejecutaPara qué sirve
init() Antes de mostrar la ventana Preparar datos: cargar archivos, crear colecciones iniciales
start(Stage) Cuando la app está lista para mostrar la ventana Crear la interfaz: controles, layouts, eventos, CSS
stop() Cuando el usuario cierra la ventana Limpieza: guardar datos en archivo, cerrar conexiones

Importante: Solo start() es obligatorio. init() y stop() son opcionales — los sobreescribes solo si los necesitas (ej: cargar/guardar datos).

Punto de entrada

El método launch()

Application.launch(args) es el punto de entrada de toda app JavaFX. Va en el método main y arranca todo el ciclo de vida.

public class SpotifyMiniApp extends Application {

    @Override
    public void init() {
        // Se ejecuta PRIMERO — cargar datos del archivo
        System.out.println("1. init() — Preparando datos...");
    }

    @Override
    public void start(Stage stage) {
        // Se ejecuta SEGUNDO — crear la interfaz
        System.out.println("2. start() — Creando ventana...");
        stage.setTitle("Spotify Mini");
        stage.setScene(new Scene(new VBox(), 600, 400));
        stage.show();
    }

    @Override
    public void stop() {
        // Se ejecuta AL CERRAR — guardar datos
        System.out.println("3. stop() — Guardando datos...");
    }

    public static void main(String[] args) {
        launch(args);   // Esto dispara init() → start() → ... → stop()
    }
}

Pregunta para pensar: Si necesitas que tu app cargue las canciones guardadas de un archivo cuando abre, ¿en qué método pondrías ese código?

Layouts

VBox — Apilar verticalmente

VBox organiza sus elementos hijos uno debajo del otro. Es el layout más simple y el más usado.

import javafx.scene.layout.VBox;
import javafx.geometry.Insets;

VBox root = new VBox(10);    // 10 = espacio entre elementos (en px)
root.setPadding(new Insets(20));  // Margen interior de 20px
root.getChildren().addAll(titulo, txtCancion, txtArtista, btnAgregar);
VBox(10)

TextField: canción
TextField: artista
Button: Agregar
Layouts

HBox — Organizar horizontalmente

HBox organiza sus elementos hijos uno al lado del otro. Útil para barras de botones o filas de controles.

import javafx.scene.layout.HBox;

HBox botones = new HBox(10);   // 10px de espacio entre botones
botones.getChildren().addAll(btnAgregar, btnLimpiar, btnGuardar);
HBox(10)
Agregar
Limpiar
Guardar

Combinar VBox y HBox

Puedes poner un HBox dentro de un VBox (o al revés). Así creas layouts más complejos: formulario vertical con una fila de botones horizontal al final.

GridPane — Formularios organizados

GridPane organiza elementos en una grilla de filas y columnas. Ideal para formularios tipo "etiqueta : campo".

import javafx.scene.layout.GridPane;

GridPane form = new GridPane();
form.setHgap(10);    // Espacio horizontal entre columnas
form.setVgap(10);    // Espacio vertical entre filas

//                   columna, fila
form.add(lblTitulo,     0,      0);
form.add(txtTitulo,     1,      0);
form.add(lblArtista,    0,      1);
form.add(txtArtista,    1,      1);
form.add(lblDuracion,   0,      2);

Interacción

Eventos — Conectar la interfaz con la lógica

En la consola, el usuario escribía y el programa leía con Scanner. En JavaFX, el usuario hace clic y el programa reacciona.

// El botón "Agregar" lee los campos y crea una canción
btnAgregar.setOnAction(e -> {
    String titulo = txtTitulo.getText();
    String artista = txtArtista.getText();
    String duracion = txtDuracion.getText();

    if (titulo.isEmpty() || artista.isEmpty()) {
        lblEstado.setText("Completa todos los campos");
        return;
    }

    Cancion nueva = new Cancion(titulo, artista, duracion);
    canciones.add(nueva);
    actualizarLista();
    txtTitulo.clear();
    txtArtista.clear();
    txtDuracion.clear();
    lblEstado.setText("Canción agregada: " + titulo);
});

El patrón es siempre el mismo:

1. Leer datos de los TextField con getText()
2. Validar que no estén vacíos
3. Crear el objeto y agregarlo a la colección
4. Actualizar la vista (un TextArea o Label)
5. Limpiar los campos con clear()

Mostrar datos

TextArea como lista visual

Para mostrar la lista de canciones, usamos un TextArea en modo solo lectura. Cada vez que cambia la colección, reconstruimos el texto.

import javafx.scene.control.TextArea;

TextArea areaLista = new TextArea();
areaLista.setEditable(false);    // Solo lectura
areaLista.setPrefRowCount(10);   // Altura preferida

// Método para actualizar la lista visual
private void actualizarLista() {
    StringBuilder sb = new StringBuilder();
    for (int i = 0; i < canciones.size(); i++) {
        Cancion c = canciones.get(i);
        sb.append((i + 1) + ". " + c.toString() + "\n");
    }
    areaLista.setText(sb.toString());
}

¿Por qué TextArea y no algo más sofisticado? Porque es simple, funciona, y no necesita conocimientos avanzados. En futuras unidades podrías usar ListView o TableView, pero para empezar esto es suficiente.

Persistencia

Guardar y cargar desde .txt

Para que los datos no se pierdan al cerrar la app, los guardamos en un archivo de texto. Formato: una canción por línea, campos separados por |.

import java.io.*;
import java.util.ArrayList;

// GUARDAR canciones en archivo
private void guardarCanciones() {
    try (BufferedWriter writer = new BufferedWriter(new FileWriter("canciones.txt"))) {
        for (Cancion c : canciones) {
            writer.write(c.getTitulo() + "|" + c.getArtista() + "|" + c.getDuracion());
            writer.newLine();
        }
    } catch (IOException e) {
        System.out.println("Error al guardar: " + e.getMessage());
    }
}

// CARGAR canciones desde archivo
private void cargarCanciones() {
    File archivo = new File("canciones.txt");
    if (!archivo.exists()) return;   // Si no existe, no hay nada que cargar

    try (BufferedReader reader = new BufferedReader(new FileReader(archivo))) {
        String linea;
        while ((linea = reader.readLine()) != null) {
            String[] partes = linea.split("\\|");
            if (partes.length == 3) {
                canciones.add(new Cancion(partes[0], partes[1], partes[2]));
            }
        }
    } catch (IOException e) {
        System.out.println("Error al cargar: " + e.getMessage());
    }
}
Persistencia + Ciclo de vida

¿Dónde va cada método?

Ahora conectamos la persistencia con el ciclo de vida de la aplicación:

init()
cargarCanciones()
→
start(Stage)
crear interfaz
→
App corriendo
el usuario interactúa
→
stop()
guardarCanciones()
@Override
public void init() {
    canciones = new ArrayList<>();
    cargarCanciones();    // Leer del archivo al iniciar
}

@Override
public void stop() {
    guardarCanciones();   // Guardar al cerrar
}

Resultado: El usuario agrega canciones, cierra la app, la vuelve a abrir, y las canciones siguen ahí. Los datos persisten entre ejecuciones.
