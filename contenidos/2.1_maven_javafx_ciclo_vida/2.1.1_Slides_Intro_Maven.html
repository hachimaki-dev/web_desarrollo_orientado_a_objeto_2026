Unidad 2.1 · Introducción a Maven

Maven

El gestor de proyectos que organiza tu código, tus dependencias y tu vida.

🛸
Motivación

¿Qué hacíamos antes?

Hasta ahora, programaste en Java con un solo archivo o con pocos archivos en una carpeta. Todo lo que necesitabas ya venía incluido en Java (Scanner, ArrayList, etc.).

Pero ahora necesitamos algo nuevo

Queremos crear ventanas con botones, campos de texto y diseño visual. Eso no viene incluido en Java por defecto.

Necesitamos agregar una librería externa llamada JavaFX.

Sin Maven, eso significa...

Descargar archivos JAR manualmente de internet.

Configurar rutas en tu IDE a mano.

Compartir el proyecto con compañeros y que no les funcione.

Actualizar una librería y romper todo.

Analogía: Es como armar un mueble sin instrucciones, sin lista de piezas, y sin herramientas. Puedes hacerlo... pero vas a sufrir.

Concepto

Maven = gestor de proyectos

Maven es una herramienta que automatiza la organización de un proyecto Java. Hace tres cosas fundamentales:

1. Estructura

Define dónde va cada archivo: tu código Java, tus recursos (CSS, imágenes), lo compilado.

2. Dependencias

Descarga automáticamente las librerías externas que necesitas (como JavaFX). Tú solo escribes el nombre.

3. Compilación

Compila y ejecuta tu proyecto con un solo comando. Sin configurar rutas ni classpaths.

Analogía IKEA: Maven es como comprar un mueble en IKEA. Te viene con las piezas correctas, las instrucciones paso a paso, y las herramientas necesarias. Tú solo armas.

Estructura

Estructura de carpetas Maven

Todo proyecto Maven tiene la misma estructura. Esto significa que cualquier desarrollador que abra tu proyecto sabe exactamente dónde buscar cada cosa.

spotify-mini/
├── pom.xml                 ← El "plano" del proyecto
├── src/
│   └── main/
│       ├── java/           ← Tu código Java va aquí
│       │   └── com/spotify/mini/
│       │       ├── SpotifyMiniApp.java
│       │       └── Cancion.java
│       └── resources/      ← Archivos extra (CSS, imágenes)
│           └── styles.css
└── target/               ← Lo que Maven compila (no tocar)

Regla de oro: Tu código va en src/main/java/. Tus archivos extra (CSS, imágenes) van en src/main/resources/. La carpeta target/ la genera Maven — nunca la edites.

El archivo central

El pom.xml — Identidad del proyecto

El pom.xml (Project Object Model) es el archivo más importante de un proyecto Maven. Contiene toda la información que Maven necesita para construir tu proyecto.

Tiene 3 partes esenciales:

<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
         http://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <!-- PARTE 1: Identidad del proyecto -->
    <groupId>com.spotify.mini</groupId>     <!-- "Apellido" del proyecto -->
    <artifactId>spotify-mini</artifactId>   <!-- "Nombre" del proyecto -->
    <version>1.0</version>                  <!-- Versión actual -->

    <!-- PARTE 2: Dependencias (lo que necesitas) -->
    <dependencies>
        <!-- Aquí se agregan las librerías externas -->
    </dependencies>

    <!-- PARTE 3: Plugins (cómo compilar y ejecutar) -->
    <build>
        <plugins>...</plugins>
    </build>
</project>

Analogía: El pom.xml es como la lista de compras del supermercado. Le dices a Maven qué necesitas, y Maven lo descarga por ti.

Dependencias

¿Qué es una dependencia?

Una dependencia es una librería externa que tu proyecto necesita para funcionar. En vez de descargar archivos JAR manualmente, le dices a Maven qué necesitas y qué versión.

<dependencies>
    <!-- JavaFX: para crear interfaces gráficas -->
    <dependency>
        <groupId>org.openjfx</groupId>
        <artifactId>javafx-controls</artifactId>
        <version>21.0.2</version>
    </dependency>
</dependencies>
¿De dónde las descarga Maven?

De un repositorio público en internet llamado Maven Central. Es como una tienda de apps, pero para librerías Java.

¿Qué pasa cuando agregas una?

Maven la descarga automáticamente, la guarda en tu computador, y la hace disponible para tu código. No necesitas hacer nada más.

Cada dependencia tiene 3 datos: groupId (quién la hizo), artifactId (nombre de la librería), version (qué versión usar).

Ejecución

Ciclo de vida básico de Maven

Maven tiene un ciclo de vida: una secuencia de fases que se ejecutan en orden. Para este curso, solo necesitas conocer tres:

mvn compile
→
mvn exec:java
→
mvn package
mvn compile

Compila tu código Java. Convierte tus archivos .java en archivos .class que la máquina entiende.

mvn exec:java

Ejecuta tu aplicación directamente. Es el equivalente a darle "Play" en tu IDE.

mvn package

Empaqueta todo en un archivo .jar que puedes compartir. Como "exportar" tu proyecto.

En VS Code no necesitas escribir estos comandos a mano. El Java Extension Pack te permite ejecutar con un clic o con F5. Pero es bueno saber qué pasa por detrás.

En tu IDE

Maven en VS Code

Con el Java Extension Pack instalado, VS Code detecta automáticamente los proyectos Maven.

Lo que VS Code hace por ti:

Detecta el pom.xml y descarga las dependencias automáticamente.

Muestra el proyecto con su estructura de carpetas Maven.

Ofrece un panel "Maven" en la barra lateral con las fases del ciclo de vida.

Te permite ejecutar con F5 o clic derecho → "Run".

Cómo crear un proyecto Maven:

1. Ctrl+Shift+P → "Java: Create Java Project"

2. Seleccionar "Maven"

3. Elegir el archetype "maven-archetype-quickstart"

4. Definir groupId y artifactId

5. VS Code crea la estructura completa

No te preocupes si esto suena a mucho. En la guía de actividad vas a seguir los pasos uno por uno. Aquí solo importa que entiendas el concepto.
