¿Dónde ponemos el código SQL dentro de nuestro proyecto?

En la Unidad 2 trabajábamos con archivos .json locales. Ahora que daremos el salto a un motor relacional real como Oracle Database, la primera decisión ingenieril que debemos tomar antes de crear las carpetas del proyecto es: ¿qué clase será la encargada de escribir y ejecutar las sentencias INSERT, SELECT, UPDATE y DELETE?

Si lo pensamos, existen tres alternativas posibles:

Alternativa A (Descartada)

Escribir el SQL dentro de la Vista (UsuarioView)

Poner el INSERT INTO directo dentro del botón «Guardar». Es una mala práctica grave: mezcla código gráfico con base de datos y hace imposible mantener el proyecto.

Alternativa B (Descartada)

Escribir el SQL dentro del Controlador

El Controlador debe encargarse de validar reglas de negocio (por ejemplo, que no vengan campos vacíos), no de abrir conexiones de red ni recorrer cursores SQL.

Alternativa C (Nuestra Elección ✓)

Crear una capa DAO (UsuarioDAO)

Aislamos todo el SQL en una clase dedicada llamada DAO (Data Access Object). Si mañana cambia la base de datos, la Vista y el Controlador no se tocan.

El flujo de comunicación y la estructura de paquetes

Con esta decisión tomada, el antiguo Manager que leía JSON en la Unidad 2 evoluciona hacia dos clases especializadas: ConexionDB (que abre la conexión con Oracle) y UsuarioDAO (que ejecuta las consultas SQL y devuelve objetos Usuario).

1.2 Ejecutar el script de creación de usuario_desarrollador

Una vez conectado como administrador (SYS en laboratorio o SYSTEM en Docker), abre una hoja de trabajo SQL (New SQL Worksheet) y ejecuta el siguiente bloque completo:

Hoja SQL (Conectado como Administrador SYS o SYSTEM) ORACLE SQL 
-- Habilita la creación de usuarios con nombres normales en Oracle 12c/19c/21c/23ai
ALTER SESSION SET "_ORACLE_SCRIPT"=TRUE;

-- Crear el usuario de trabajo con contraseña 123456
CREATE USER usuario_desarrollador IDENTIFIED BY "123456"
DEFAULT TABLESPACE "USERS"
TEMPORARY TABLESPACE "TEMP";

-- Asignar cuota de almacenamiento y permisos básicos
ALTER USER usuario_desarrollador QUOTA UNLIMITED ON USERS;
GRANT CREATE SESSION TO usuario_desarrollador;
GRANT "RESOURCE" TO usuario_desarrollador;
ALTER USER usuario_desarrollador DEFAULT ROLE "RESOURCE";
¿Por qué hacemos esto línea por línea?
  • ALTER SESSION SET "_ORACLE_SCRIPT"=TRUE;: Desde Oracle 12c, el motor exige que los usuarios globales lleven el prefijo C##. Esta instrucción desactiva esa restricción en la sesión actual para poder llamarlo limpiamente usuario_desarrollador.
  • DEFAULT TABLESPACE "USERS" y QUOTA UNLIMITED ON USERS: Define en qué espacio físico del disco se guardarán nuestras tablas y le autoriza a escribir datos sin límite de megabytes.
  • GRANT CREATE SESSION y GRANT "RESOURCE": Un usuario recién creado en Oracle no tiene permiso ni siquiera para iniciar sesión. CREATE SESSION le permite conectarse y RESOURCE le permite crear tablas y secuencias.

1.4 Diseñar y crear la tabla USUARIOS

Ahora sí, abre una hoja SQL dentro de la conexión de usuario_desarrollador.

Antes de ejecutar el CREATE TABLE, fijémonos en cómo definiremos la clave primaria id. Cuando una persona crea una cuenta en un formulario, ella escribe su nombre de usuario, correo y contraseña, pero no inventa su propio número de ID. Por eso declaramos la columna id como NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY: así Oracle lleva un contador interno automático (1, 2, 3...) cada vez que insertamos un registro.

Ejecuta este script en la hoja SQL de usuario_desarrollador:

Hoja SQL (Conectado como usuario_desarrollador) ORACLE SQL 
CREATE TABLE usuarios (
    id NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    username VARCHAR2(50) NOT NULL UNIQUE,
    correo VARCHAR2(100) NOT NULL,
    password VARCHAR2(100) NOT NULL,
    rol VARCHAR2(30) NOT NULL
);

-- Insertamos 2 registros iniciales de prueba (observa que NO enviamos el id)
INSERT INTO usuarios (username, correo, password, rol)
VALUES ('admin_duoc', 'admin@duoc.cl', 'admin123', 'ADMIN');

INSERT INTO usuarios (username, correo, password, rol)
VALUES ('carlitos_dev', 'carlitos@duoc.cl', 'java2026', 'DOCENTE');

-- Confirmamos la transacción para que los datos sean visibles desde Java
COMMIT;

-- Verificamos que las 2 filas existan con sus IDs 1 y 2
SELECT * FROM usuarios;
Comprobemos: ¿Te quedó así?

Al ejecutar el SELECT * FROM usuarios; al final del script, deberías ver en el panel inferior de VS Code una tabla con 2 filas: admin_duoc con ID = 1 y carlitos_dev con ID = 2. Recuerda ejecutar siempre COMMIT; cuando insertes datos manualmente en SQL Developer, o de lo contrario tu programa Java verá la tabla vacía.

Agregar el Driver JDBC de Oracle (ojdbc11) en Maven

¿Por qué hacemos esto? Java incluye de fábrica el paquete java.sql.* (conocido como JDBC), que trae interfaces estándar como Connection, PreparedStatement y ResultSet. Sin embargo, Java por sí solo no conoce el protocolo privado de red de Oracle Database.

Para que nuestro programa Java pueda hablar con Oracle en el puerto 1521 y además construir ventanas con JavaFX, nuestro archivo pom.xml necesita dos dependencias: javafx-controls y el driver oficial de Oracle (ojdbc11). Reemplaza el contenido de tu pom.xml por este archivo completo:

Construir y probar el puente de conexión (ConexionDB.java)

Ahora crearemos una clase encargada exclusivamente de entregar conexiones abiertas hacia Oracle.

Aquí hay un detalle técnico fundamental de Oracle JDBC que debes conocer: la estructura de la cadena URL cambia en un símbolo dependiendo de si te conectas a un SID (en el Laboratorio de Duoc) o a un Service Name (en Docker gvenzl/oracle-free):

  • Por SID (Lab Duoc): Se escribe con dos puntos (:) después del puerto ➔ jdbc:oracle:thin:@localhost:1521:ORCL
  • Por Service Name (Docker en Casa): Se escribe con doble barra (//) y barra simple (/) ➔ jdbc:oracle:thin:@//localhost:1521/FREEPDB1

Dejaremos ambas líneas escritas en nuestra clase para que cuando vayas del laboratorio a tu casa solo tengas que comentar una línea y descomentar la otra. Crea el archivo ConexionDB.java dentro del paquete database:

src/main/java/com/hachimakidev/userapp/database/ConexionDB.java JAVA 
package com.hachimakidev.userapp.database;

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.SQLException;

public class ConexionDB {

    // OPCIÓN A: Para Laboratorio Duoc (Conexión por SID usa ':ORCL')
    private static final String URL = "jdbc:oracle:thin:@localhost:1521:ORCL";

    // OPCIÓN B: Para Casa con Docker gvenzl/oracle-free (Service Name usa '//' y '/FREEPDB1')
    // private static final String URL = "jdbc:oracle:thin:@//localhost:1521/FREEPDB1";

    private static final String USER = "usuario_desarrollador";
    private static final String PASS = "123456";

    public static Connection obtenerConexion() throws SQLException {
        return DriverManager.getConnection(URL, USER, PASS);
    }

    // Método main temporal solo para comprobar que el puente funciona
    public static void main(String[] args) {
        try (Connection conn = obtenerConexion()) {
            System.out.println("¡CONEXIÓN EXITOSA A ORACLE DATABASE!");
        } catch (SQLException e) {
            System.out.println("Error al conectar: " + e.getMessage());
        }
    }
}
¿Por qué escribimos este código así?
  • private static final String URL / USER / PASS: Son constantes (final) que pertenecen a la clase (static) y nadie desde fuera puede alterar (private).
  • public static Connection obtenerConexion() throws SQLException: Al ser un método static, cuando más adelante estemos en el DAO no necesitaremos hacer new ConexionDB(); bastará con escribir ConexionDB.obtenerConexion().
  • try (Connection conn = obtenerConexion()): Esta estructura con paréntesis después del try se llama try-with-resources. Garantiza que Java cierre automáticamente la conexión con Oracle apenas termine el bloque try.
Comprobemos antes de avanzar: Ejecuta ConexionDB.java

Regla de oro ingenieril: jamás avances a programar las demás clases sin comprobar que tu conexión responde. Haz clic en Run sobre el main de ConexionDB.java. Si en la consola aparece ¡CONEXIÓN EXITOSA A ORACLE DATABASE!, estamos listos para continuar.

Diseñar la clase Usuario.java aplicando Sobrecarga de Constructores

¿Qué prosigue ahora? Necesitamos una clase Java que represente en memoria cada fila de la tabla USUARIOS que creamos en Oracle. Como la tabla tiene 5 columnas (id, username, correo, password, rol), nuestra clase tendrá exactamente esos 5 atributos privados.

El problema del atributo id al crear vs. al leer

Detengámonos un segundo a pensar cómo se usará esta clase en dos momentos distintos del programa:

  1. Cuando el usuario llena el formulario y presiona «Guardar» (INSERT): En ese instante tenemos el username, el correo, el password y el rol, pero todavía NO existe el id, porque recuerdas que Oracle lo genera automáticamente con GENERATED ALWAYS AS IDENTITY recién cuando el dato entra a la tabla.
  2. Cuando traemos las filas desde Oracle con un SELECT (o editamos una fila en la tabla): Ahí el registro sí trae su id numérico (1, 2, 3...) desde la base de datos, y necesitamos guardarlo dentro del objeto Usuario para mostrarlo en la TableView y saber qué fila actualizar o eliminar.

¿Cómo resolvemos esto de forma limpia en Programación Orientada a Objetos? Aplicando Sobrecarga de Constructores: creamos un constructor con 5 parámetros (con id) y un segundo constructor con 4 parámetros (sin id).

src/main/java/com/hachimakidev/userapp/model/Usuario.java JAVA 
package com.hachimakidev.userapp.model;

public class Usuario {

    private int id;
    private String username;
    private String correo;
    private String password;
    private String rol;

    // Constructor 1: CON id (Lo usa el DAO al hacer SELECT y el Controlador al hacer UPDATE)
    public Usuario(int id, String username, String correo, String password, String rol) {
        this.id = id;
        this.username = username;
        this.correo = correo;
        this.password = password;
        this.rol = rol;
    }

    // Constructor 2: SIN id (Lo usa el Controlador cuando creamos una cuenta nueva con INSERT)
    public Usuario(String username, String correo, String password, String rol) {
        this.username = username;
        this.correo = correo;
        this.password = password;
        this.rol = rol;
    }

    public int getId() {
        return id;
    }

    public void setId(int id) {
        this.id = id;
    }

    public String getUsername() {
        return username;
    }

    public void setUsername(String username) {
        this.username = username;
    }

    public String getCorreo() {
        return correo;
    }

    public void setCorreo(String correo) {
        this.correo = correo;
    }

    public String getPassword() {
        return password;
    }

    public void setPassword(String password) {
        this.password = password;
    }

    public String getRol() {
        return rol;
    }

    public void setRol(String rol) {
        this.rol = rol;
    }
}
Comprobemos: ¿Por qué son tan importantes los nombres de los Getters aquí?

Verifica que tus métodos se llamen exactamente getId(), getUsername(), getCorreo(), getPassword() y getRol(). Más adelante, las columnas de la TableView buscarán automáticamente esos nombres exactos para mostrar los datos en pantalla.

Programar el Patrón DAO paso a paso (INSERT, SELECT, UPDATE y DELETE)

Llegamos a la pieza nueva más importante de la Unidad 3: la clase UsuarioDAO. Para no abrumarnos con un archivo gigante de golpe, lo iremos armando método por método y entendiendo cómo funciona cada uno.

Antes de empezar: ¿Cómo enviamos variables dentro de una consulta SQL?

Cuando necesitamos insertar los datos de un objeto Usuario en SQL, existen dos formas de armar el texto de la consulta en Java:

Forma A: Concatenar con '+' (Peligrosa)

Statement tradicional

Escribir "INSERT INTO usuarios VALUES ('" + u.getUsername() + "')". Es propenso a errores de comillas y vulnerable a ataques de Inyección SQL.

Forma B: Parámetros '?' (Estándar Profesional ✓)

PreparedStatement

Escribimos signos de interrogación ? como comodines (VALUES (?, ?, ?, ?)) y luego los llenamos de forma segura por su posición (1, 2, 3, 4) usando ps.setString(...).

5.1 Crear el esqueleto de UsuarioDAO.java y el primer método: guardar() (INSERT)

Crea el archivo UsuarioDAO.java dentro del paquete dao y escribe primero el método guardar(Usuario usuario):

src/main/java/com/hachimakidev/userapp/dao/UsuarioDAO.java (Parte 1: INSERT) JAVA 
package com.hachimakidev.userapp.dao;

import com.hachimakidev.userapp.database.ConexionDB;
import com.hachimakidev.userapp.model.Usuario;

import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.util.ArrayList;

public class UsuarioDAO {

    // 1. OPERACIÓN CREAR (INSERT)
    public boolean guardar(Usuario usuario) {
        String sql = "INSERT INTO usuarios (username, correo, password, rol) VALUES (?, ?, ?, ?)";

        try (Connection conn = ConexionDB.obtenerConexion();
             PreparedStatement ps = conn.prepareStatement(sql)) {

            ps.setString(1, usuario.getUsername());
            ps.setString(2, usuario.getCorreo());
            ps.setString(3, usuario.getPassword());
            ps.setString(4, usuario.getRol());

            int filasAfectadas = ps.executeUpdate();
            return filasAfectadas > 0;

        } catch (SQLException e) {
            System.out.println("Error al guardar usuario: " + e.getMessage());
            return false;
        }
    }
}
Analicemos qué hace cada línea de guardar()
  • String sql = "INSERT INTO usuarios (username, correo, password, rol) VALUES (?, ?, ?, ?)";: Declaramos las 4 columnas (sin id) y dejamos 4 signos de interrogación ? esperando sus valores.
  • ps.setString(1, usuario.getUsername());: En JDBC los signos ? se numeran empezando desde el 1 (de izquierda a derecha). El 1 es username, el 2 es correo, el 3 es password y el 4 es rol.
  • int filasAfectadas = ps.executeUpdate();: Para cualquier orden que modifique datos en la tabla (INSERT, UPDATE o DELETE), usamos executeUpdate(). Este método ejecuta el SQL en Oracle (con auto-commit automático en JDBC) y devuelve cuántas filas se insertaron. Si es mayor que 0, retornamos true.

5.2 Agregar el segundo método: obtenerTodos() (SELECT)

Ahora necesitamos leer todas las filas guardadas en Oracle para poder mostrarlas en nuestra TableView.

Cuando ejecutamos una consulta SELECT, en lugar de executeUpdate() usamos ps.executeQuery(). Este método nos devuelve un objeto llamado ResultSet, que puedes imaginar como una hoja de cálculo donde hay un puntero que parte arriba de la primera fila. Cada vez que llamamos a while (rs.next()), el puntero baja una fila, extraemos sus 5 columnas, fabricamos un objeto new Usuario(...) y lo metemos a un ArrayList.

Agrega este método debajo de guardar() dentro de UsuarioDAO.java:

UsuarioDAO.java (Parte 2: Agregar método obtenerTodos) JAVA 
    // 2. OPERACIÓN LEER TODOS (SELECT)
    public ArrayList<Usuario> obtenerTodos() {
        ArrayList<Usuario> lista = new ArrayList<>();
        String sql = "SELECT id, username, correo, password, rol FROM usuarios ORDER BY id ASC";

        try (Connection conn = ConexionDB.obtenerConexion();
             PreparedStatement ps = conn.prepareStatement(sql);
             ResultSet rs = ps.executeQuery()) {

            while (rs.next()) {
                int id = rs.getInt("id");
                String username = rs.getString("username");
                String correo = rs.getString("correo");
                String password = rs.getString("password");
                String rol = rs.getString("rol");

                Usuario u = new Usuario(id, username, correo, password, rol);
                lista.add(u);
            }

        } catch (SQLException e) {
            System.out.println("Error al listar usuarios: " + e.getMessage());
        }
        return lista;
    }
¿Por qué aquí usamos el constructor de 5 parámetros?
  • Observa la línea Usuario u = new Usuario(id, username, correo, password, rol);. Como el registro ya viene desde Oracle, extraemos su número de id real con rs.getInt("id") y usamos el constructor que incluye el id.

5.3 Agregar los métodos actualizar() (UPDATE) y eliminar() (DELETE)

Para completar el CRUD en nuestro DAO, agregaremos la edición y el borrado. En ambos casos es indispensable incluir la condición WHERE id = ? para que Oracle modifique o borre únicamente la fila seleccionada y no toda la tabla.

Agrega estos dos métodos al final de tu clase UsuarioDAO.java:

UsuarioDAO.java (Parte 3: Agregar métodos actualizar y eliminar) JAVA 
    // 3. OPERACIÓN ACTUALIZAR (UPDATE)

Construir el Controlador (UsuarioController.java)

¿Por qué mantenemos un Controlador si ya tenemos el DAO? Porque la Vista trabaja con cajas de texto crudas (String) que el usuario puede dejar en blanco por descuido. El rol del Controlador es actuar como un filtro de seguridad:

  1. Recibe los datos enviados por la Vista.
  2. Comprueba que ningún campo obligatorio venga vacío (isBlank()).
  3. Si todo es válido, arma el objeto new Usuario(...) y llama al UsuarioDAO. Si algún dato falta, detiene la operación de inmediato y devuelve false sin molestar a Oracle.

Crea el archivo UsuarioController.java dentro del paquete controller:

package com.hachimakidev.userapp.controller;

import com.hachimakidev.userapp.dao.UsuarioDAO;
import com.hachimakidev.userapp.model.Usuario;
import java.util.ArrayList;

public class UsuarioController {

    private UsuarioDAO usuarioDAO;

    public UsuarioController() {
        this.usuarioDAO = new UsuarioDAO();
    }

    public boolean registrarUsuario(String username, String correo, String password, String rol) {
        if (username == null || username.isBlank() ||
            correo == null || correo.isBlank() ||
            password == null || password.isBlank() ||
            rol == null || rol.isBlank()) {
            return false;
        }

        // Usamos el constructor SIN id porque es un usuario nuevo
        Usuario nuevo = new Usuario(username.trim(), correo.trim(), password, rol);
        return usuarioDAO.guardar(nuevo);
    }

    public ArrayList<Usuario> obtenerUsuarios() {
        return usuarioDAO.obtenerTodos();
    }

    public boolean actualizarUsuario(int id, String username, String correo, String password, String rol) {
        if (id <= 0 ||
            username == null || username.isBlank() ||
            correo == null || correo.isBlank() ||
            password == null || password.isBlank() ||
            rol == null || rol.isBlank()) {
            return false;
        }

        // Usamos el constructor CON id para indicar qué fila se está actualizando
        Usuario editado = new Usuario(id, username.trim(), correo.trim(), password, rol);
        return usuarioDAO.actualizar(editado);
    }

    public boolean eliminarUsuario(int id) {
        if (id <= 0) {
            return false;
        }
        return usuarioDAO.eliminar(id);
    }
}

7.2 ¿Cómo resolvemos el problema de seleccionar un usuario para Editar o Eliminar?

Piensa en esto: para actualizar o borrar un registro en Oracle, el UsuarioController nos pide el int id de ese usuario. Pero en nuestro formulario izquierdo no hay ninguna caja de texto para escribir el id (porque no queremos que el usuario lo escriba a mano ni lo invente). ¿De dónde sacamos el id entonces?

Lo sacamos directamente de la fila que el usuario seleccione con el ratón en la TableView:

  1. Declaramos un atributo en la vista llamado private int idSeleccionado = -1; (vale -1 cuando no hay nada seleccionado).
  2. Le agregamos un escuchador (Listener) a la tabla: cuando el usuario hace clic sobre una fila, tomamos el objeto Usuario de esa fila, guardamos su getId() dentro de idSeleccionado y rellenamos automáticamente los TextField con sus datos actuales.
  3. Así, cuando presione el botón «Actualizar» o «Eliminar», le enviaremos ese idSeleccionado al Controlador.

            lblEstado.setText("Error: Completa todos los campos o cambia el username.");
        }
    }

    private void accionActualizar() {
        if (idSeleccionado == -1) {
            lblEstado.setText("Selecciona primero un usuario en la tabla.");
            return;
        }

        boolean exito = controller.actualizarUsuario(
                idSeleccionado,
                txtUsername.getText(),
                txtCorreo.getText(),
                txtPassword.getText(),
                cmbRol.getValue()
        );

        if (exito) {
            lblEstado.setText("Usuario ID #" + idSeleccionado + " actualizado.");
            limpiarFormulario();
            cargarDatosEnTabla();
        } else {
            lblEstado.setText("Error al actualizar los datos.");
        }
    }

    private void accionEliminar() {
        if (idSeleccionado == -1) {
            lblEstado.setText("Selecciona primero un usuario en la tabla.");
            return;
        }

        boolean exito = controller.eliminarUsuario(idSeleccionado);

        if (exito) {
            lblEstado.setText("Usuario eliminado de Oracle.");
            limpiarFormulario();
            cargarDatosEnTabla();
        } else {
            lblEstado.setText("No se pudo eliminar el usuario.");
        }
    }

    private void cargarDatosEnTabla() {
        ObservableList<Usuario> datos = FXCollections.observableArrayList(
                controller.obtenerUsuarios()
        );
        tablaUsuarios.setItems(datos);
    }

    private void limpiarFormulario() {
        idSeleccionado = -1;
        txtUsername.clear();
        txtCorreo.clear();
        txtPassword.clear();
        cmbRol.setValue(null);
        tablaUsuarios.getSelectionModel().clearSelection();
    }
}

8.2 Extensión Práctica: ¿Y cómo se hace un Login con este mismo DAO?

Una vez que dominas el CRUD anterior, surge una pregunta muy común: «Profe, ¿y si en el proyecto nos piden una ventana de Login antes de entrar al sistema?».

Un Login no es más que una consulta SELECT con un filtro WHERE username = ? AND password = ? dentro de tu mismo UsuarioDAO. Si Oracle encuentra una fila que coincida con ambos datos, rs.next() devuelve true y retornamos el objeto Usuario encontrado; si no coincide ninguna fila, retornamos null:

1. En UsuarioDAO.java: Método autenticar(...) JAVA 
    // 5. OPERACIÓN LOGIN (SELECT CON WHERE)
    public Usuario autenticar(String username, String password) {
        String sql = "SELECT id, username, correo, password, rol FROM usuarios "
                   + "WHERE username = ? AND password = ?";

        try (Connection conn = ConexionDB.obtenerConexion();
             PreparedStatement ps = conn.prepareStatement(sql)) {

            ps.setString(1, username);
            ps.setString(2, password);

            try (ResultSet rs = ps.executeQuery()) {
                if (rs.next()) {
                    return new Usuario(
                            rs.getInt("id"),
                            rs.getString("username"),
                            rs.getString("correo"),
                            rs.getString("password"),
                            rs.getString("rol")
                    );
                }
            }
        } catch (SQLException e) {
            System.out.println("Error al autenticar: " + e.getMessage());
        }
        return null; // Retorna null si las credenciales son incorrectas
    }
2. En UsuarioController.java y UsuarioView.java: Cómo consumirlo JAVA

public Usuario iniciarSesion(String username, String password) {
    if (username == null || username.isBlank() ||
        password == null || password.isBlank()) {
