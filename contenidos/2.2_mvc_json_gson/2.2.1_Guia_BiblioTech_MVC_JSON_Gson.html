Fase 0 — Entender el problema antes de escribir código Qué hay que construir y qué preguntas debemos responder

El encargo

La biblioteca BiblioTech necesita una pantalla donde el bibliotecario escriba el RUT de un usuario y, al presionar Buscar, vea su nombre y su correo. Si el RUT no está registrado, la pantalla debe decirlo.

Esta es la aplicación terminada. Pruébala con 12345678-9, con 98765432-1, con un RUT inventado y con el campo vacío:

Las preguntas de análisis

Antes de abrir el editor, un programador responde qué tiene que hacer el programa. Cada respuesta se convertirá en una parte del código.

Pregunta Respuesta en BiblioTech
¿Qué información maneja el programa? Usuarios. Cada usuario tiene RUT, nombre y correo.
¿Dónde están guardados esos datos? En un archivo de texto con formato JSON que viene dentro del proyecto.
¿Quién lee ese archivo y busca un usuario por RUT? Una clase que administre la lista de usuarios.
¿Quién muestra la información en pantalla? La ventana de JavaFX.
Cuando se presiona Buscar, ¿quién decide a qué clase pedirle el usuario? Un intermediario entre la ventana y los datos.

¿Por qué no escribir todo en start()?

Podríamos meter todo en un solo método: leer el archivo, crear la ventana y buscar al hacer clic. Funcionaría. Así se vería:

public void start(Stage stage) {
    // 1. Leer el archivo de usuarios
    //    ... 10 líneas para abrir el archivo y convertirlo ...

    // 2. Crear la ventana
    TextField txf_rut = new TextField();
    Button btn_buscar = new Button("Buscar");
    //    ... 10 líneas más de Label, HBox, VBox ...

    // 3. Buscar al hacer clic
    btn_buscar.setOnAction(evento -> {
        //    ... recorrer la lista, comparar RUT, actualizar los Label ...
    });
}

El problema aparece cuando el programa crece:

  • Si los usuarios pasan a estar en una base de datos, hay que editar el mismo método que dibuja la ventana.
  • Si la búsqueda falla, hay que revisar un método con lectura de archivos, botones y etiquetas mezclados.
  • Si otra pantalla necesita buscar usuarios, no puede reutilizar nada: la búsqueda está atrapada dentro del botón.

La tabla de arriba ya separó tres responsabilidades: los datos, la pantalla y el intermediario. Darle a cada una su propia clase tiene nombre: patrón MVC.

Fase 1 — El patrón MVC Qué es un patrón de diseño y qué le corresponde a cada capa

¿Qué es un patrón de diseño?

Un patrón de diseño es una solución probada a un problema que se repite al programar. No es una librería ni algo que se descarga: es una forma de repartir responsabilidades entre clases que muchos programadores ya usaron y les funcionó. Conocer el patrón permite que otra persona abra tu proyecto y sepa dónde buscar cada cosa.

MVC: Modelo, Vista, Controlador

MVC divide la aplicación en tres capas. Cada una tiene una responsabilidad y, tan importante como eso, cosas que no debe hacer.

Capa Su responsabilidad Lo que no debe hacer En BiblioTech
Modelo Representar los datos, cargarlos y buscarlos. Crear botones, etiquetas o ventanas. User, UserManager
Vista Mostrar información y recibir lo que hace el usuario (escribir, hacer clic). Leer archivos o recorrer la lista de usuarios. UserDataView, HomeView
Controlador Recibir los pedidos de la vista, prepararlos y pasárselos al modelo. Dibujar en pantalla o guardar los datos él mismo. UserController

Una analogía: el restaurante

Vista = la sala y la mesa

El cliente ve la carta, hace su pedido y recibe el plato. No sabe cómo se cocina.

Controlador = el mesero

Toma el pedido, lo lleva a la cocina y vuelve con el plato. No cocina.

Modelo = la cocina

Tiene los ingredientes y sabe prepararlos. No atiende mesas.

JSON = la despensa

Donde están guardados los ingredientes. Solo la cocina entra ahí.

El cliente nunca entra a la cocina. En código: la vista nunca le pide datos directamente al modelo, siempre pasa por el controlador.

Fase 2 — Crear el proyecto Maven sin arquetipo Un proyecto mínimo donde sabemos para qué está cada archivo

1
Crea el proyecto en VS Code

Un arquetipo es una plantilla: crea el proyecto con clases, pruebas y configuraciones de ejemplo ya escritas. Vamos a crearlo sin arquetipo para partir de lo mínimo y agregar cada archivo sabiendo por qué está ahí.

  1. Presiona Ctrl+Shift+P para abrir la paleta de comandos.
  2. Escribe Java: Create Java Project y selecciónalo.
  3. Elige Maven.
  4. Elige No Archetype...
  5. Como group Id escribe com.hachimakidev.bibliotech
  6. Como artifact Id escribe bibliotech
  7. Elige la carpeta donde se guardará el proyecto.
Dato Qué significa
groupId Identifica a quién pertenece el proyecto. Por convención es un dominio al revés (como hachimakidev.com → com.hachimakidev). Se usa también como nombre del paquete principal.
artifactId El nombre del proyecto. Es el nombre de la carpeta y del archivo que Maven genera al empaquetar.

Usa exactamente esos valores. Si cambias el groupId, los nombres de paquete de esta guía no van a calzar con los tuyos.

VS Code crea esta estructura:

bibliotech/
├── pom.xml                  configuración de Maven
└── src/
    ├── main/
    │   ├── java/            el código Java (.java)
    │   │   └── com/hachimakidev/bibliotech/
    │   │       └── Main.java
    │   └── resources/       archivos que no son código pero el programa necesita
    └── test/
        └── java/            pruebas automáticas (no las usaremos)

Cuando compiles, aparecerá una carpeta target/. Ahí Maven deja los archivos .class compilados. No se edita a mano.

Si alguna carpeta no aparece (por ejemplo resources), créala: clic derecho sobre la carpeta padre → New Folder.

2
Configura el pom.xml

El pom.xml es la ficha del proyecto: cómo se llama, con qué versión de Java se compila y qué librerías necesita. Reemplaza su contenido por este:

Código
Por qué está
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns=... xsi:schemaLocation=...>

Indican que el archivo es XML y qué reglas sigue. VS Code las usa para autocompletar y marcar errores. No se modifican.

<modelVersion>4.0.0</modelVersion>

Versión del formato del pom.xml. Siempre es 4.0.0.

<groupId>...</groupId>
<artifactId>...</artifactId>
<version>1.0-SNAPSHOT</version>

La identidad del proyecto. SNAPSHOT significa "versión en desarrollo, todavía no terminada".

<maven.compiler.source>21</maven.compiler.source>
<maven.compiler.target>21</maven.compiler.target>

Le dicen a Maven que el código está escrito en Java 21 y que se compila para ejecutarse en Java 21.

<project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>

Indica cómo están codificados los caracteres de tus archivos .java. Con UTF-8, los textos con tilde o ñ, como "Usuario no encontrado." o "—", se compilan sin deformarse.

<dependency>
    <groupId>org.openjfx</groupId>
    <artifactId>javafx-controls</artifactId>
    <version>21.0.1</version>
</dependency>

JavaFX no viene incluido en Java. Esta dependencia le pide a Maven que lo descargue y lo agregue al proyecto. javafx-controls trae Stage, Scene, Label, Button, TextField y los layouts.

¿Qué pasa si borro esta dependencia?

Todos los import javafx... quedan en rojo: el compilador no encuentra esas clases y el proyecto no compila.

Después de guardar, VS Code puede preguntar si quieres sincronizar la configuración de Maven. Acepta. La primera vez tarda unos segundos porque descarga JavaFX.

Gson todavía no está en el pom. Lo agregaremos en la Fase 6, cuando lo necesitemos. Así sabes exactamente qué línea del pom permite usar Gson.

3
Crea BiblioTechApp y Main, y prueba que la ventana abre

Antes de escribir lógica, comprobamos que JavaFX funciona. En src/main/java/com/hachimakidev/bibliotech/ crea BiblioTechApp.java:

package com.hachimakidev.bibliotech;

import javafx.application.Application;
import javafx.scene.Scene;
import javafx.scene.layout.VBox;
import javafx.stage.Stage;

public class BiblioTechApp extends Application {

    @Override
    public void start(Stage stage) {
        stage.setTitle("BiblioTech");
        stage.setScene(new Scene(new VBox(), 600, 300));
        stage.show();
    }

    public static void main(String[] args) {
        launch(args);
    }

}

Es la estructura que ya conoces: start recibe el Stage, le asignamos una Scene (por ahora con un VBox vacío) y la mostramos. En la Fase 8 cambiaremos el VBox vacío por la vista real.

Luego reemplaza el contenido de Main.java por:

package com.hachimakidev.bibliotech;

public class Main {
    public static void main(String[] args) {
        BiblioTechApp.main(args);
    }
}

¿Por qué existe Main si BiblioTechApp ya tiene main?

Cuando ejecutas directamente una clase que extiende Application, Java revisa antes de partir que JavaFX esté instalado como módulo del sistema. En nuestro proyecto JavaFX llega por Maven, como una librería más, así que esa revisión falla con el error "faltan los componentes de JavaFX runtime".

Main no extiende Application, así que Java no hace esa revisión. Main solo llama a BiblioTechApp.main(), que llama a launch(), y JavaFX arranca normalmente.

Checkpoint

Abre Main.java → clic derecho → Run Java. Debe abrirse una ventana vacía con el título BiblioTech.

Si en la consola aparece "ADVERTENCIA: Unsupported JavaFX configuration: classes were loaded from 'unnamed module'", no es un error. JavaFX avisa que se cargó como librería y no como módulo. La app funciona igual.

Fase 3 — Paquetes model, view y controller Llevar las capas de MVC a carpetas

4
Crea los tres paquetes

Un paquete es una carpeta de clases Java. Ya estás usando uno: com.hachimakidev.bibliotech corresponde a la carpeta com/hachimakidev/bibliotech/. Vamos a crear un subpaquete por cada capa de MVC, para que la separación se vea al abrir el proyecto.

Clic derecho sobre la carpeta bibliotech (la que contiene Main.java) → New Folder, tres veces:

src/main/java/com/hachimakidev/bibliotech/
├── controller/   el intermediario
├── model/        los datos y su lógica
├── view/         las pantallas
├── BiblioTechApp.java
└── Main.java

La línea package

La primera línea de cada archivo .java declara en qué paquete está. Tiene que coincidir con la ruta de carpetas a partir de src/main/java. Una clase en model/ empieza con:

package com.hachimakidev.bibliotech.model;

Usar una clase de otro paquete

Desde otro paquete, una clase solo se puede usar si es public y si se importa con su nombre completo:

import com.hachimakidev.bibliotech.model.User;

Los import también muestran cómo se conectan las capas: si un archivo de view importa algo de model para buscar datos, se está saltando al controlador.

Fase 4 — JSON: el formato de los datos Guardar los usuarios fuera del código Java

El problema

Podríamos crear los usuarios dentro del código:

lista_usuarios.add(new User("12345678-9", "Juan Pérez", "juan.perez@example.com"));
lista_usuarios.add(new User("98765432-1", "María López", "maria.lopez@example.com"));

Pero así, para agregar o corregir un usuario hay que editar Java y volver a compilar. Los datos deberían estar en un archivo separado, con un formato que una persona pueda leer y que un programa pueda interpretar sin ambigüedad.

¿Qué es JSON?

JSON (JavaScript Object Notation) es un formato de texto para representar datos. Aunque el nombre dice JavaScript, lo usan casi todos los lenguajes, incluido Java. Es un archivo de texto común que sigue unas pocas reglas:

Regla Ejemplo
Un objeto va entre llaves { } y contiene pares "clave": valor. { "rut": "12345678-9" }
Las claves siempre van entre comillas dobles. "nombre"
Los textos van entre comillas dobles. Los números y true/false van sin comillas. "Juan", 25, true
Los pares se separan con coma. Después del último par no va coma. { "a": 1, "b": 2 }
Un arreglo (lista) va entre corchetes [ ] y sus elementos se separan con coma. [ {...}, {...} ]

El mismo usuario en Java y en JSON

En Java (un objeto en memoria)

User u = new User(
    "12345678-9",
    "Juan Pérez",
    "juan.perez@example.com"
);

En JSON (texto en un archivo)

{
  "rut": "12345678-9",
  "nombre": "Juan Pérez",
  "correo": "juan.perez@example.com"
}

Cada clave del JSON corresponde a un atributo de la clase User. Un ArrayList<User> se escribe en JSON como un arreglo [ ] de objetos.

Clic derecho sobre src/main/resources → New File → users.json:

Código
Qué significa
[

El archivo completo es un arreglo: una lista de usuarios. Este detalle importa en la Fase 6, cuando le digamos a Gson qué tipo de dato construir.

  {
    "rut": "12345678-9",
    "nombre": "Juan Pérez",
    "correo": "juan.perez@example.com"
  },

Un objeto = un usuario. Las claves rut, nombre y correo serán los nombres de los atributos de User.

La coma después de } separa este usuario del siguiente.

  {
    "rut": "98765432-1",
    ...
  }

Segundo usuario. Es el último, así que después de su } no va coma.

]

Cierra el arreglo.

¿Por qué en resources?

Al compilar, Maven hace dos cosas: convierte los .java de src/main/java en .class, y copia todo lo que está en src/main/resources. Ambos terminan en la misma carpeta: target/classes.

target/classes/
├── com/hachimakidev/bibliotech/
│   ├── Main.class
│   └── ... el resto de clases compiladas
└── users.json   copiado desde src/main/resources

Esa carpeta, donde Java busca las clases del programa mientras se ejecuta, se llama classpath. Como users.json queda en el classpath, el programa lo encuentra siempre en el mismo lugar, sin importar en qué carpeta del computador esté guardado el proyecto. En la Fase 6 veremos el método que lo busca ahí.

Fase 5 — El modelo User La clase que representa a un usuario

6
Crea model/User.java

Ya sabes escribir una clase como esta. Lo nuevo es dónde va (en model, porque representa datos) y una regla que impone Gson.

package com.hachimakidev.bibliotech.model;

public class User {
    private String rut;
    private String nombre;
    private String correo;

    public User() {}

    public User(String rut, String nombre, String correo) {
        this.rut = rut;
        this.nombre = nombre;
        this.correo = correo;
    }

    public String getRut() { return rut; }
    public String getNombre() { return nombre; }
    public String getCorreo() { return correo; }
}
Código
Por qué está
package com.hachimakidev.bibliotech.model;

El archivo está en la carpeta model. User es parte del Modelo: representa un dato, no dibuja nada ni recibe clics.

private String rut;
private String nombre;
private String correo;

La regla de Gson: los nombres de los atributos deben ser idénticos a las claves del JSON, incluyendo mayúsculas y minúsculas. Gson toma la clave "rut" y busca un atributo llamado rut.

¿Qué pasa si renombro correo a email?

El código compila y no aparece ningún error. Gson encuentra la clave "correo" en el JSON, no encuentra un atributo con ese nombre y la ignora. email queda en null y la app muestra "Correo: null". Es un error silencioso.

public User() {}

Constructor vacío. Gson crea cada objeto en dos pasos: primero lo crea vacío con este constructor y luego escribe cada atributo con el valor de la clave que tiene el mismo nombre.

¿Qué pasa si lo borro?

En este proyecto seguiría funcionando, porque Gson tiene un mecanismo interno de respaldo para crear objetos sin constructor vacío. Igual se declara: es la forma documentada en que Gson crea objetos y evita depender de ese respaldo.

public User(String rut, String nombre, String correo) { ... }

Constructor con parámetros, para crear un User desde nuestro propio código. Gson no lo usa.

public String getRut() { return rut; }
public String getNombre() { return nombre; }
public String getCorreo() { return correo; }

Los atributos son privados. La vista necesita leerlos para mostrarlos, así que exponemos getters.

No hay setters porque en esta parte nadie modifica un usuario: solo se leen.

Fase 6 — Gson y UserManager Leer el archivo JSON y convertirlo en objetos Java línea por línea

¿Qué es una librería externa?

Java incluye en su kit de desarrollo estándar (JDK) muchas clases útiles: ArrayList, String, Math o System. Sin embargo, Java estándar no incluye un lector de archivos JSON.

Para no escribir cientos de líneas de código manual que analicen comillas, llaves y corchetes, los programadores recurren a librerías externas: código ya escrito, probado y empaquetado por otros equipos. Gson es una librería desarrollada por Google cuyo único propósito es convertir texto en formato JSON a objetos de Java (y viceversa).

7
Agrega la dependencia de Gson en el pom.xml

Abre pom.xml y agrega el bloque de Gson dentro de la etiqueta <dependencies>, justo debajo de JavaFX:

        <dependency>
            <groupId>com.google.code.gson</groupId>
            <artifactId>gson</artifactId>
            <version>2.14.0</version>
        </dependency>

Al guardar el archivo pom.xml, Maven descarga automáticamente el archivo empaquetado de Gson desde Internet y lo deja disponible para todas las clases de tu proyecto.

¿Qué pasa si borro esta dependencia?

Al intentar escribir import com.google.gson.Gson; en tu código, el compilador marcará un error en rojo: "The import com.google.gson cannot be resolved". Tu código no sabrá qué es Gson.

8
Crea model/UserManager.java

Dentro de la carpeta src/main/java/com/hachimakidev/bibliotech/model/ crea el archivo UserManager.java. Esta clase pertenece al Modelo: su responsabilidad es mantener la lista de usuarios en memoria, cargarlos desde el archivo y buscar a un usuario cuando se lo soliciten.

Escribe el siguiente código completo:

package com.hachimakidev.bibliotech.model;

import java.io.InputStream;
import java.io.InputStreamReader;
import java.util.ArrayList;

import com.google.gson.Gson;

public class UserManager {

    private ArrayList<User> lista_usuarios = new ArrayList<>();
    private boolean datos_cargados = false;

    public UserManager() {
        cargarDatos();
    }

    private void cargarDatos() {
        try {
            InputStream stream = getClass().getResourceAsStream("/users.json");

            InputStreamReader reader = new InputStreamReader(stream);

            Gson gson = new Gson();
            User[] arreglo_usuarios = gson.fromJson(reader, User[].class);

            for (User u : arreglo_usuarios) {
                lista_usuarios.add(u);
            }

            datos_cargados = true;

        } catch (Exception e) {
            System.out.println("Error al cargar users.json: " + e);
        }
    }

    public boolean isDatosCargados() {
        return datos_cargados;
    }

    public User buscarPorRut(String rut_a_buscar) {
        for (User u : lista_usuarios) {
            if (u.getRut().equals(rut_a_buscar)) {
                return u;
            }
        }
        return null;
    }
}

Explicación línea por línea de UserManager

Línea de código
Por qué existe y qué hace
private ArrayList<User> lista_usuarios = new ArrayList<>();

Es la lista dinámica donde guardamos todos los objetos User en la memoria RAM del programa. Al ser privada, ninguna otra clase puede modificar o borrar elementos directamente.

private boolean datos_cargados = false;

Es una bandera de estado (flag). Comienza en false. Solo cambiará a true si el archivo se leyó y procesó sin ningún error. Permite saber si el sistema tiene datos listos para operar.

public UserManager() {
    cargarDatos();
}

El constructor de la clase. Al crear un new UserManager(), se ejecuta inmediatamente cargarDatos() para que los usuarios queden disponibles desde el primer segundo.

InputStream stream = getClass().getResourceAsStream("/users.json");

¿Cómo encuentra Java el archivo? El archivo users.json no está guardado en una carpeta estática del disco duro como C:\archivos. Está empaquetado dentro de tu aplicación en el classpath.

El método getClass().getResourceAsStream("/users.json") le dice a Java: "Busca el recurso llamado users.json en la raíz del classpath del programa y abre un canal de lectura".

¿Qué pasa si borro la barra diagonal / inicial?

Si escribes "users.json" sin /, Java no buscará en la raíz del classpath, sino dentro de la carpeta del paquete actual (com/hachimakidev/bibliotech/model/users.json). Como el archivo no está ahí, stream devolverá null y la carga fallará.

InputStreamReader reader = new InputStreamReader(stream);

Bytes vs. Caracteres: Un InputStream entrega solo números binarios crudos (bytes). Pero nuestro JSON está escrito en texto con letras, acentos y signos de puntuación.

InputStreamReader actúa como un adaptador de traducción: toma los bytes del flujo y los decodifica en caracteres legibles de texto para que puedan ser interpretados.

Gson gson = new Gson();

Crea el objeto convertidor proporcionado por la librería externa Gson.

User[] arreglo_usuarios = gson.fromJson(reader, User[].class);

El método fromJson realiza la conversión completa:

  1. Lee los caracteres a través del reader.
  2. Identifica que el archivo comienza con un corchete [, correspondiente a un arreglo.
  3. Por cada bloque { ... }, crea una instancia de User y llena sus atributos rut, nombre y correo.
  4. Retorna todos los usuarios agrupados en un arreglo de tipo User[].

Usamos User[].class porque es la forma directa en que Java le indica a Gson: "El resultado que espero es un arreglo de objetos User".

for (User u : arreglo_usuarios) {
    lista_usuarios.add(u);
}

Un arreglo común (User[]) tiene tamaño fijo. Usamos el ciclo for tradicional que ya conoces para pasar cada usuario al ArrayList (lista_usuarios), donde podremos consultar y operar con flexibilidad.

datos_cargados = true;

Si la ejecución llegó hasta este punto sin interrupciones, confirmamos que todos los usuarios fueron cargados con éxito.

} catch (Exception e) {
    System.out.println("Error al cargar users.json: " + e);
}

Si el archivo no se encuentra, o si alguien escribió una coma incorrecta en el JSON, Java lanza una excepción. El bloque catch captura el problema, imprime el diagnóstico detallado en la consola técnica y evita que la aplicación se congele o se cierre de golpe.

Como datos_cargados permanece en false, el resto de la aplicación sabrá que no hay datos disponibles.

public User buscarPorRut(String rut_a_buscar) {
    for (User u : lista_usuarios) {
        if (u.getRut().equals(rut_a_buscar)) {
            return u;
        }
    }
    return null;
}

El algoritmo de búsqueda lineal:

  1. Recorre cada usuario u de lista_usuarios.
  2. Compara el RUT del usuario con el RUT solicitado usando .equals() (nunca con ==, porque en Java los Strings son objetos).
  3. Si coincide, retorna inmediatamente el objeto u encontrado (deteniendo el ciclo).
  4. Si el ciclo termina de revisar toda la lista y no hubo coincidencias, retorna null.

Fase 7 — El controlador El intermediario que comunica la pantalla con los datos

En el patrón MVC, la Vista nunca debe comunicarse directamente con el Modelo. Si la ventana llamara directo a UserManager, la interfaz gráfica quedaría acoplada a la forma en que se almacenan los datos. Si mañana los datos vienen de una base de datos o de Internet, tendrías que reescribir la ventana.

El Controlador es el puente: recibe la acción de la pantalla, limpia y valida la entrada, le solicita el resultado al modelo y responde a la vista.

package com.hachimakidev.bibliotech.view;

import com.hachimakidev.bibliotech.controller.UserController;
import com.hachimakidev.bibliotech.model.User;

import javafx.geometry.Insets;
import javafx.scene.control.Button;
import javafx.scene.control.Label;
import javafx.scene.control.TextField;
import javafx.scene.layout.HBox;
import javafx.scene.layout.VBox;

public class UserDataView {

    public VBox userData() {

        UserController controller = new UserController();

        Label lbl_user_rut = new Label("RUT del usuario:");
        TextField txf_user_rut = new TextField();
        txf_user_rut.setPromptText("Ej: 12345678-9");
        Button btn_buscar = new Button("Buscar");

        Label lbl_resultado = new Label();
        Label lbl_rut = new Label("RUT: —");
        Label lbl_nombre = new Label("Nombre: —");
        Label lbl_correo = new Label("Correo: —");

        btn_buscar.setOnAction(evento -> {
            lbl_rut.setText("RUT: —");
            lbl_nombre.setText("Nombre: —");
            lbl_correo.setText("Correo: —");

            String rut_ingresado = txf_user_rut.getText();

            if (!controller.datosDisponibles()) {
                lbl_resultado.setText("Error: no se pudieron cargar los datos de usuarios.");
            } else if (rut_ingresado.isBlank()) {
                lbl_resultado.setText("Escribe un RUT antes de buscar.");
            } else {
                User usuario = controller.buscarUsuario(rut_ingresado);

                if (usuario != null) {
                    lbl_resultado.setText("Usuario encontrado.");
                    lbl_rut.setText("RUT: " + usuario.getRut());
                    lbl_nombre.setText("Nombre: " + usuario.getNombre());
                    lbl_correo.setText("Correo: " + usuario.getCorreo());
                } else {
                    lbl_resultado.setText("Usuario no encontrado.");
                }
            }
        });

        HBox fila_busqueda = new HBox(10, lbl_user_rut, txf_user_rut, btn_buscar);
        VBox box = new VBox(10, fila_busqueda, lbl_resultado, lbl_rut, lbl_nombre, lbl_correo);
        box.setPadding(new Insets(20));

        return box;
    }

}

Fase 10 — Recorrido completo El viaje de un dato desde el clic del ratón hasta la pantalla

Cuando el operador hace clic en Buscar con el RUT 12345678-9, el sistema ejecuta esta secuencia exacta a través de las tres capas de la arquitectura MVC:

  • 1. Evento en la Vista: El usuario presiona el Button. Se dispara el listener btn_buscar.setOnAction() en UserDataView.
  • 2. Petición al Controlador: La vista obtiene el texto del TextField y llama al método controller.buscarUsuario("12345678-9") en UserController.
  • 3. Limpieza y delegación: El controlador limpia los espacios con .trim() y le solicita el usuario al modelo: manager.buscarPorRut("12345678-9").
  • 4. Búsqueda en el Modelo: UserManager recorre con un for su ArrayList<User> en memoria RAM (previamente cargado desde users.json con Gson).
  • 5. Coincidencia: Al encontrar la coincidencia con .equals(), retorna la referencia del objeto User encontrado.
  • 6. Retorno al Controlador: El controlador recibe el objeto User y se lo devuelve a la vista.
  • 7. Renderizado en pantalla: La vista recibe el objeto, extrae los valores con usuario.getNombre() y actualiza los Label correspondientes.

Lectura directa a ArrayList con TypeToken

En este tutorial aprendiste a leer el JSON convirtiéndolo primero en un arreglo tradicional: gson.fromJson(reader, User[].class) y luego volcándolo a un ArrayList con un for. Esta forma es directa y comprensible porque ya dominas arreglos y bucles.

Sin embargo, en Java profesional verás con frecuencia esta línea alternativa que lee directamente a una lista sin usar arreglos:

Type tipoLista = new TypeToken<ArrayList<User>>() {}.getType();
lista_usuarios = gson.fromJson(reader, tipoLista);

¿Por qué existe TypeToken? En Java ocurre un fenómeno llamado Type Erasure (borrado de tipos). Cuando compilas tu código, Java elimina la información genérica: en tiempo de ejecución solo existe ArrayList, pero Java ya no recuerda si era una lista de User, de String o de Integer.

Si intentas escribir gson.fromJson(reader, ArrayList<User>.class), el compilador no lo permite. Para resolver esto, los creadores de Gson diseñaron la clase auxiliar TypeToken, que utiliza reflexión interna para capturar y conservar el tipo completo ArrayList<User>.

Ambas alternativas son válidas y producen exactamente el mismo resultado en memoria.
