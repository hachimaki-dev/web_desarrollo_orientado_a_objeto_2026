Fase 0 — ¿Por qué MVC? Fundamentación, Propósito y Arquitectura Por qué nunca debemos programar todo en una única clase y cómo pensar en capas

Cuando los estudiantes comienzan a programar interfaces gráficas, el impulso natural es escribir todo en un solo archivo: crear la ventana, colocar el botón, abrir el archivo JSON dentro del evento setOnAction, leer los datos y pintar la tabla ahí mismo.

El peligro del código espagueti: Si juntas la lectura del archivo, la lógica de decisión y la interfaz en el mismo archivo, cualquier cambio visual (por ejemplo, cambiar un botón por un menú) puede romper la carga de datos. Y peor aún: el día que los datos vengan de una base de datos SQL en vez de un JSON, tendrás que reescribir toda la pantalla desde cero.

La Analogía del Restaurante para entender MVC

Para visualizar claramente las tres responsabilidades, piensa en cómo opera un restaurante profesional:

Capa Equivalente en el Restaurante Responsabilidad en Software Lo que NUNCA debe hacer
VISTA (View) El Mozo y la Carta del Menú Muestra la información al usuario en pantalla de forma atractiva y detecta clics o pulsaciones de teclas. Cocinar los platos o comprar carne (no debe leer archivos JSON ni calcular lógica).
CONTROLADOR (Controller) El Administrador / Despachador Recibe la orden del mozo, valida lo que se pidió y le solicita el trabajo a la cocina. Devuelve el resultado a la vista. Dibujar botones en pantalla ni manipular directamente las conexiones a bajo nivel.
MODELO (Model) La Cocina y la Despensa Guarda los datos del negocio (Libros, Revistas) y administra de dónde se leen o guardan (persistencia). Saber cómo se llama el botón o qué color tiene la ventana.

Fase 1 — El Modelo POO con Herencia: Material, Libro y Revista Construcción progresiva de la jerarquía de clases con explicación línea por línea

Tanto los libros como las revistas comparten características comunes: ambos tienen un título y una imagen de portada. En lugar de duplicar estos atributos en dos clases separadas, aplicamos el principio de herencia.

String titulo;

Atributos comunes a todo material. titulo guarda el texto del nombre y imagen almacena la dirección URL donde está alojada la portada en internet.

public Material(String titulo, String imagen) {
    this.titulo = titulo;
    this.imagen = imagen;

Constructor de la clase base. Obliga a que cualquier material nazca con un título y una portada definidos.

public String getTitulo() { return titulo; }
public String getImagen() { return imagen; }

¡Punto crucial para JavaFX! La tabla TableView requiere métodos que comiencen con get seguidos del nombre del atributo con mayúscula (getTitulo, getImagen) para poder leer los valores automáticamente mediante reflexión.

¿Qué pasa si borro getTitulo() o lo renombro a dameTitulo()?

La tabla JavaFX no sabrá cómo obtener el valor y la columna "Título" aparecerá completamente vacía en blanco, sin dar error de compilación explícito.

        this.autor = autor;

Línea de Código
Análisis Pedagógico y Propósito
public class Libro extends Material {

La palabra clave extends establece la relación de herencia («un Libro es un Material»). Automáticamente hereda los atributos y métodos de Material.

super(titulo, imagen);

Invoca al constructor de la clase padre Material. La clase padre es quien debe inicializar titulo e imagen. Luego, el constructor de Libro se encarga de sus propios atributos (autor y paginas).

¿Qué pasa si no pongo super(titulo, imagen)?

Java intentará llamar a un constructor sin parámetros super() en Material. Como Material solo tiene un constructor con parámetros, el código no compilará arrojando el error: «Implicit super constructor Material() is undefined».

Fase 2 — El Origen de Datos y MaterialManager con Gson Desglose paso a paso: ¿Por qué necesitamos JsonObject y switch-case?

Aquí es donde muchos estudiantes se confunden: ¿Por qué no leemos el archivo con un simple new Gson().fromJson(...) directamente a Material[]?

El Gran Dilema Pedagógico: En el archivo JSON tenemos elementos heterogéneos: unos son libros (con autor y páginas) y otros son revistas (con editorial y periodicidad). Si le pidiéramos a Gson que cree objetos Material directamente, Gson no sabría qué clase hija construir y se perderían los datos específicos.

La Solución Profesional: Leemos cada elemento primero como un objeto JSON genérico (JsonObject). Luego leemos su campo discriminador "tipo" y mediante un switch-case decidimos si construimos un Libro o una Revista.

Modelo · Gestor de Persistencia 📄 src/main/java/com/hachimakidev/biblioapp/model/MaterialManager.java
Imports requeridos: java.io.InputStream, java.io.InputStreamReader, java.util.ArrayList, com.google.gson.Gson, com.google.gson.JsonObject 
package com.hachimakidev.biblioapp.model;

import java.io.InputStream;
import java.io.InputStreamReader;
import java.util.ArrayList;

import com.google.gson.Gson;
import com.google.gson.JsonObject;

public class MaterialManager {

    ArrayList<Material> material_arraylist = new ArrayList<>();

    public MaterialManager() {
        loadMaterial();
    }

    public void loadMaterial() {

        InputStream stream =
                getClass().getResourceAsStream("/biblioteca.json");

        if (stream == null) {
            throw new IllegalStateException(
                    "No se encontró biblioteca.json en resources");
        }

        try (InputStreamReader reader = new InputStreamReader(stream)) {

            Gson gson = new Gson();

            JsonObject[] materiales =
                    gson.fromJson(reader, JsonObject[].class);

            for (JsonObject material : materiales) {

                String tipo = material.get("tipo").getAsString();

                switch (tipo) {

                    case "libro":

                        String titulo =
                                material.get("titulo").getAsString();

                        String autor =
                                material.get("autor").getAsString();

                        int paginas =
                                material.get("paginas").getAsInt();

                        String imagen =
                                material.get("imagen").getAsString();

                        Libro libro =
                                new Libro(titulo, imagen, autor, paginas);

                        material_arraylist.add(libro);

                        break;

                    case "revista":

                        String tituloRevista =
                                material.get("titulo").getAsString();

                        String editorial =
                                material.get("editorial").getAsString();

                        String imagenRevista =
                                material.get("imagen").getAsString();

                        String periodicidad =
                                material.get("periodicidad").getAsString();

                        Revista revista = new Revista(
                                tituloRevista,
                                imagenRevista,
                                editorial,
                                periodicidad
                        );

                        material_arraylist.add(revista);

                        break;

                    default:
                        System.out.println(
                                "Tipo de material desconocido: " + tipo);
                        break;
                }
            }

        } catch (java.io.IOException e) {
            throw new IllegalStateException(
                    "No se pudo leer biblioteca.json", e);
        }
    }

    public ArrayList<Material> getMateriales() {
        return material_arraylist;
    }

    public void mostrarMateriales() {
        for (Material material : material_arraylist) {
            System.out.println(material.getTitulo());
        }
    }
}

Análisis Pedagógico, Propósito y Resolución
ArrayList<Material> material_arraylist = new ArrayList<>();

Polimorfismo puro: La lista almacena referencias de tipo Material. Esto nos permite guardar tanto objetos Libro como objetos Revista en la misma colección sin necesidad de crear dos listas separadas.

InputStream stream = getClass().getResourceAsStream("/biblioteca.json");

Busca el archivo dentro de src/main/resources a través del Classpath. La barra inicial "/" indica que la búsqueda parte desde la raíz de los recursos compilados.

if (stream == null) {
    throw new IllegalStateException("No se encontró biblioteca.json en resources");
}

Programación defensiva: Si el archivo no está en la carpeta correcta o el nombre está mal escrito, stream vale null. Lanzamos una excepción clara de inmediato para avisarle al programador exactamente qué ocurrió.

try (InputStreamReader reader = new InputStreamReader(stream))

Try-with-resources: Convierte los bytes binarios del stream en caracteres de texto legibles. Al declararse entre los paréntesis del try, Java garantiza que el archivo se cerrará automáticamente al finalizar, evitando fugas de memoria.

¿Qué pasa si no usamos try-with-resources?

El archivo podría quedar abierto y bloqueado en el sistema operativo, consumiendo recursos de memoria innecesarios.

JsonObject[] materiales = gson.fromJson(reader, JsonObject[].class);

El núcleo de la solución Gson: Transforma el arreglo JSON en un arreglo de objetos genéricos JsonObject[]. En este punto no hemos creado libros ni revistas todavía: solo tenemos cajas genéricas de datos.

for (JsonObject material : materiales) {
    String tipo = material.get("tipo").getAsString();

Iteramos cada objeto y consultamos el valor del campo "tipo". Este valor actúa como discriminador (nos dice si es "libro" o "revista").

switch (tipo) {
    case "libro":
        // ...
        Libro libro = new Libro(titulo, imagen, autor, paginas);
        material_arraylist.add(libro);
        break;

Según el tipo, extraemos los atributos específicos (usando getAsInt() para números y getAsString() para texto), construimos la instancia concreta de Libro y la agregamos a la lista polimórfica.

Fase 4 — La Vista Gráfica: Dominando el Nodo TableView ¿Qué es una TableView, qué significa su tipado genérico y cómo funciona PropertyValueFactory?

¿Qué es una TableView en JavaFX? Es un componente visual de alto nivel diseñado para mostrar colecciones de objetos en formato de filas y columnas. A diferencia de crear decenas de etiquetas Label a mano, la TableView se encarga automáticamente de los encabezados, la selección de filas y la barra de desplazamiento (scroll).

Los Tres Conceptos Fundamentales de TableView

Concepto Sintaxis en Código Explicación Pedagógica
Tipado de la Tabla TableView<Material> El tipo entre diamantes indica qué objeto representa cada fila de la tabla.
Columna Tipada TableColumn<Material, String> Tiene dos tipos: el primero (Material) es el objeto de la fila; el segundo (String) es el tipo de dato que contiene esa celda.
Extracción de Propiedad new PropertyValueFactory<>("titulo") Usa reflexión en Java: busca en el objeto un método llamado getTitulo() para extraer el valor automáticamente.
Lista Observable ObservableList<Material> Una lista especial de JavaFX que avisa a la tabla cada vez que se agrega o quita un elemento para que se repinte sola.
Vista · Interfaz Gráfica 📄 src/main/java/com/hachimakidev/biblioapp/view/MaterialView.java (Versión Base) 
package com.hachimakidev.biblioapp.view;

import com.hachimakidev.biblioapp.controller.MaterialController;
import com.hachimakidev.biblioapp.model.Material;

import javafx.collections.FXCollections;
import javafx.collections.ObservableList;
import javafx.scene.Scene;
import javafx.scene.control.TableColumn;
import javafx.scene.control.TableView;
import javafx.scene.control.cell.PropertyValueFactory;
import javafx.scene.layout.VBox;

public class MaterialView {

    private TableView<Material> tablaMateriales;
    private MaterialController materialController;

    public MaterialView() {
        materialController = new MaterialController();

        configurarTabla();
        cargarMateriales();
    }

    private void configurarTabla() {

        tablaMateriales = new TableView<>();

        TableColumn<Material, String> columnaTitulo =
                new TableColumn<>("Título");

        columnaTitulo.setCellValueFactory(
                new PropertyValueFactory<>("titulo"));

        TableColumn<Material, String> columnaImagen =
                new TableColumn<>("Portada");

        columnaImagen.setCellValueFactory(
                new PropertyValueFactory<>("imagen"));

        tablaMateriales.getColumns().add(columnaTitulo);
        tablaMateriales.getColumns().add(columnaImagen);
    }

    private void cargarMateriales() {

        ObservableList<Material> materiales =
                FXCollections.observableArrayList(
                        materialController.getMateriales());

        tablaMateriales.setItems(materiales);
    }

    public Scene materialScene() {

        VBox contenedor = new VBox(tablaMateriales);

        Scene escena = new Scene(contenedor, 800, 600);

        return escena;
    }
}
Línea de Código
Análisis Pedagógico y Fundamentación
tablaMateriales = new TableView<>();

Crea el contenedor de la tabla tipado con Material. Cada fila representará una instancia de un libro o revista del modelo.

TableColumn<Material, String> columnaTitulo = new TableColumn<>("Título");
columnaTitulo.setCellValueFactory(new PropertyValueFactory<>("titulo"));

Reflexión e Introspección: PropertyValueFactory<>("titulo") le indica a JavaFX que llame automáticamente al método getTitulo() en el objeto de esa fila para extraer su valor.

¿Qué pasa si en Material el método se llama obtenerTitulo() en vez de getTitulo()?

La columna se mostrará vacía. PropertyValueFactory exige estrictamente el estándar JavaBeans: prefijo get + NombreDePropiedad con mayúscula inicial.

ObservableList<Material> materiales =
    FXCollections.observableArrayList(materialController.getMateriales());
tablaMateriales.setItems(materiales);

El Patrón Observer: Un simple ArrayList almacena datos en memoria, pero no emite notificaciones. JavaFX exige una ObservableList para que la tabla "escuche" las adiciones o eliminaciones y se refresque sola en pantalla.

¿Qué pasa si pasamos el ArrayList directo a la tabla?

El método setItems() no compilará porque solo acepta listas que implementen la interfaz ObservableList de JavaFX.

🟢 Hito 1 de Verificación:

Si ejecutamos la aplicación aquí, la tabla funciona pero la columna "Portada" muestra el texto plano de la URL (ej: https://.../portada.jpg). La tabla ya recibe los datos del modelo, pero todavía no sabe cómo dibujar una imagen en lugar de letras.

Fase 5 — La Magia Visual: Portadas Reales con CellFactory Diferencia crucial entre setCellValueFactory y setCellFactory, TableCell e ImageView

Método Pregunta que responde ¿Qué hace exactamente?
setCellValueFactory(...) "¿Qué dato extraigo del objeto?" Obtiene el String con la ruta o URL leyendo el getter correspondiente (getImagen()).
setCellFactory(...) "¿Cómo dibujo ese dato visualmente en la pantalla?" Construye el nodo gráfico (un ImageView) y lo coloca dentro de la celda con setGraphic().

Image vs ImageView: No confundir el dato con el nodo

  • Image: Es el objeto que contiene los bytes binarios de la imagen en memoria RAM.
  • ImageView: Es el componente visual de JavaFX que sabe cómo proyectar esa Image en la escena con un ancho, alto y escala determinados.
Vista · Renderizado Gráfico 📄 src/main/java/com/hachimakidev/biblioapp/view/MaterialView.java (Personalización de Celdas)
Imports adicionales requeridos: javafx.scene.control.TableCell, javafx.scene.image.Image, javafx.scene.image.ImageView 
// 1. Configuramos altura fija para que quepan las portadas holgadamente
tablaMateriales.setFixedCellSize(110);

// 2. Personalizamos la representación gráfica de columnaImagen
columnaImagen.setCellFactory(columna -> {

    return new TableCell<Material, String>() {

        private final ImageView vistaImagen = new ImageView();

        {
            vistaImagen.setFitWidth(70);
            vistaImagen.setFitHeight(100);
            vistaImagen.setPreserveRatio(true);
        }

        @Override
        protected void updateItem(String rutaImagen, boolean vacio) {

            super.updateItem(rutaImagen, vacio);

            if (vacio || rutaImagen == null || rutaImagen.isBlank()) {

                setGraphic(null);
                setText(null);

            } else {

                // El segundo argumento (true) activa la carga asíncrona en segundo plano
                Image imagen = new Image(rutaImagen, true);

                vistaImagen.setImage(imagen);

                setGraphic(vistaImagen);
                setText(null); // Limpia el texto de la URL para que no tape la foto
            }
        }
    };
});
Línea de Código
Análisis Pedagógico y Fundamentación Técnica
tablaMateriales.setFixedCellSize(110);

Fija la altura de cada fila en 110 píxeles. Esto evita que las filas se encojan y corten la portada de 100px.

vistaImagen.setPreserveRatio(true);

Evita que las portadas se deformen o se vean estiradas si la imagen original tiene una proporción distinta a 70x100.

Image imagen = new Image(rutaImagen, true);

¡Punto crítico de rendimiento! El segundo parámetro true (background loading) descarga la imagen en un hilo secundario. Si fuera false, la ventana se congelaría por completo mientras espera la respuesta de internet.

¿Qué pasa si pongo new Image(rutaImagen, false)?

La aplicación sufrirá micro-congelamientos molestos cada vez que abras la tabla o hagas scroll, porque el Application Thread de JavaFX se detendrá esperando la red.

if (vacio || rutaImagen == null || rutaImagen.isBlank()) {
    setGraphic(null);
    setText(null);
}

Virtualización de memoria: JavaFX recicla las celdas visuales al hacer scroll. Si una celda reciclada queda vacía, debemos limpiarla con setGraphic(null) para que no muestre la imagen de una fila anterior.

Fase 7 — Proyección Arquitectónica: De MaterialManager al Patrón DAO / Repository ¿Por qué esta separación es crucial para cuando conectemos SQLite o MySQL en la Unidad 3?

🏛️ La Gran Pregunta de Diseño: ¿Por qué no leer el JSON dentro del Controller?

Imagina que en las próximas semanas el profesor indique: «Ahora la biblioteca no usará archivos JSON, sino una base de datos relacional SQLite o una API REST remota».

Si MaterialView o MaterialController tuvieran código de Gson o leyeran directamente el archivo con getResourceAsStream, tendrías que reescribir y romper toda la interfaz gráfica. 

HOY (Unidad 2):
[ MaterialView ] ──> [ MaterialController ] ──> [ MaterialManager ] ──> [ biblioteca.json ]

MAÑANA (Patrón DAO / Repository en Unidad 3):
[ MaterialView ] ──> [ MaterialController ] ──> [ MaterialRepository (Interfaz DAO) ]
                                                         │
                                    ┌────────────────────┴───────────────────┐
                                    ▼                                        ▼
                        [ JsonMaterialDAO ]                      [ SqliteMaterialDAO ]
                                    │                                        │
                                    ▼                                        ▼
                           (biblioteca.json)                         (Base de Datos SQL)

El Patrón DAO (Data Access Object) y Repository:

En la siguiente unidad formalizaremos una interfaz como esta: 

// Adelanto conceptual: Interfaz Repository / DAO
public interface MaterialRepository {
    ArrayList<Material> obtenerTodos();
    Material buscarPorTitulo(String titulo);
    void guardar(Material material);
}
🌟 El valor inmenso de lo que aprendiste hoy:

Al mantener MaterialManager aislado dentro del paquete model y comunicarte con él a través de MaterialController.getMateriales(), tu vista MaterialView ya está 100% blindada. El día que migremos a SQL, la vista no cambiará ni una sola letra. Esa es la verdadera elegancia del desacoplamiento en la Programación Orientada a Objetos.

package com.hachimakidev.biblioapp.view;

import com.hachimakidev.biblioapp.controller.MaterialController;
import com.hachimakidev.biblioapp.model.Material;

import javafx.collections.FXCollections;
import javafx.collections.ObservableList;
import javafx.scene.Scene;
import javafx.scene.control.TableCell;
import javafx.scene.control.TableColumn;
import javafx.scene.control.TableView;
import javafx.scene.control.cell.PropertyValueFactory;
import javafx.scene.image.Image;
import javafx.scene.image.ImageView;
import javafx.scene.layout.VBox;

public class MaterialView {

    private TableView<Material> tablaMateriales;
    private MaterialController materialController;

    public MaterialView() {
        materialController = new MaterialController();

        configurarTabla();
        cargarMateriales();
    }

    private void configurarTabla() {

        tablaMateriales = new TableView<>();
        tablaMateriales.setFixedCellSize(110);

        TableColumn<Material, String> columnaTitulo =
                new TableColumn<>("Título");

        columnaTitulo.setCellValueFactory(
                new PropertyValueFactory<>("titulo"));
        columnaTitulo.setPrefWidth(300);

        TableColumn<Material, String> columnaImagen =
                new TableColumn<>("Portada");

        columnaImagen.setCellValueFactory(
                new PropertyValueFactory<>("imagen"));
        columnaImagen.setPrefWidth(120);

        columnaImagen.setCellFactory(columna -> {

            return new TableCell<Material, String>() {

                private final ImageView vistaImagen = new ImageView();

                {
                    vistaImagen.setFitWidth(70);
                    vistaImagen.setFitHeight(100);
                    vistaImagen.setPreserveRatio(true);
                }

                @Override
                protected void updateItem(String rutaImagen, boolean vacio) {

                    super.updateItem(rutaImagen, vacio);

                    if (vacio || rutaImagen == null || rutaImagen.isBlank()) {

                        setGraphic(null);
                        setText(null);

                    } else {

                        Image imagen = new Image(rutaImagen, true);

                        vistaImagen.setImage(imagen);

                        setGraphic(vistaImagen);
                        setText(null);
                    }
                }
            };
        });

        tablaMateriales.getColumns().add(columnaTitulo);
        tablaMateriales.getColumns().add(columnaImagen);
    }

    private void cargarMateriales() {

        ObservableList<Material> materiales =
                FXCollections.observableArrayList(
                        materialController.getMateriales());

        tablaMateriales.setItems(materiales);
    }

    public Scene materialScene() {

        VBox contenedor = new VBox(tablaMateriales);

        Scene escena = new Scene(contenedor, 800, 600);

        return escena;
    }
}
