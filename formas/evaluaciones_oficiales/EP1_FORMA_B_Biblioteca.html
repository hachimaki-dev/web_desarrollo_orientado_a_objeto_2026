Condiciones de la evaluacion

Del entorno y la entrega

  • La evaluacion es de caracter individual. No esta permitida ninguna forma de colaboracion entre estudiantes.
  • No se permite el acceso a internet ni el uso de telefonos, relojes inteligentes ni ningun otro dispositivo externo.
  • El programa debe compilar y ejecutarse correctamente. Una solucion que no compile no permite evidenciar ningun indicador de logro.
  • El proyecto debe entregarse comprimido en formato ZIP, con tu nombre completo como nombre del archivo, en la actividad habilitada en AVA antes de que finalice la sesion.
  • No se aceptan entregas por ningun otro medio ni fuera del horario establecido. La ausencia de entrega en AVA genera automaticamente la nota minima.

De tu solucion

  • El codigo debe organizarse en clases separadas, respetando las convenciones de nomenclatura de Java: PascalCase para nombres de clase, camelCase para metodos y atributos.
  • Puedes crear metodos o clases auxiliares siempre que no contradigan los requerimientos del caso.
  • No se admite el uso de herramientas de inteligencia artificial ni de recursos digitales externos.
  • Cualquier indicio de colaboracion no autorizada, uso de IA o plagio implica la anulacion inmediata de la evaluacion con nota minima de 1.0.

Caso de negocio

Una biblioteca municipal necesita un sistema de consola en Java para gestionar el prestamo de materiales de lectura. La biblioteca maneja dos tipos de materiales: libros y revistas. Ambos comparten datos generales como titulo, autor y cantidad de ejemplares disponibles, pero se diferencian en sus atributos especificos y en la cantidad de dias permitidos para el prestamo.

El sistema debe permitir registrar materiales, listar el catalogo, buscar materiales por titulo, prestar ejemplares y ver un resumen del catalogo. Todas las entradas del usuario deben estar protegidas contra errores de ingreso.

Estructura de clases

El siguiente diagrama muestra la jerarquia de clases a implementar. La clase Material es abstracta y define la estructura base. Las clases Libro y Revista heredan de ella y sobrescriben el calculo de los dias de prestamo.

Material (abstracta)
- titulo: String
- autor: String
- cantidadDisponible: int
+ Material(titulo, autor, cantidadDisponible)
+ getTitulo(): String
+ getAutor(): String
+ getCantidadDisponible(): int
+ setCantidadDisponible(int): void
+ calcularDiasPrestamo(): int
+ mostrarInfo(): String
▲ extends
Libro
- numPaginas: int
+ Libro(titulo, autor, cantidadDisponible, numPaginas)
+ getNumPaginas(): int
+ calcularDiasPrestamo(): int
+ mostrarInfo(): String
Revista
- mesPublicacion: String
+ Revista(titulo, autor, cantidadDisponible, mesPublicacion)
+ getMesPublicacion(): String
+ calcularDiasPrestamo(): int
+ mostrarInfo(): String

Nota: Los dias de prestamo se manejan como int (dias enteros). La cantidad disponible representa el numero de ejemplares fisicos que la biblioteca tiene para prestar.

Requerimientos funcionales

A continuacion se detalla cada requerimiento. Las etiquetas IL indican que indicador de logro se evalua en cada parte.

R1 — Comentarios de paradigma IL 1.1

Al inicio de la clase Main.java, incluye un bloque de comentarios que explique:

  • Que paradigma de programacion se esta usando y sus caracteristicas principales.
  • Al menos 2 diferencias concretas entre el paradigma orientado a objetos (Java) y el paradigma que usabas antes (Python funcional). Por ejemplo: tipado, estructura del programa, compilacion vs. interpretacion, o forma de organizar el codigo.

R2 — Clase abstracta Material IL 1.3 IL 1.4

Implementa la clase abstracta Material segun el diagrama UML:

  • Atributos privados: titulo (String), autor (String), cantidadDisponible (int).
  • Constructor que reciba los 3 atributos.
  • Getters para los tres atributos y setter para cantidadDisponible.
  • Metodo abstracto calcularDiasPrestamo() que retorna int.
  • Metodo mostrarInfo() que retorna un String con el titulo, autor, dias de prestamo y cantidad disponible. Este metodo puede ser sobrescrito por las clases hijas para agregar informacion adicional.

R3 — Clase Libro IL 1.3 IL 1.4

Hereda de Material. Representa un libro de la biblioteca.

  • Atributo privado adicional: numPaginas (int).
  • Constructor que reciba los 4 parametros (3 del padre + numPaginas). Usa super().
  • Getter para numPaginas.
  • calcularDiasPrestamo(): si numPaginas es mayor a 300, retorna 14 dias. En caso contrario, retorna 7 dias.
  • mostrarInfo(): sobrescribe (@Override) el metodo del padre. Agrega el tipo ("Libro") y el numero de paginas al texto retornado.

R4 — Clase Revista IL 1.3 IL 1.4

Hereda de Material. Representa una revista de la biblioteca.

  • Atributo privado adicional: mesPublicacion (String).
  • Constructor que reciba los 4 parametros (3 del padre + mesPublicacion). Usa super().
  • Getter para mesPublicacion.
  • calcularDiasPrestamo(): retorna siempre 3 dias.
  • mostrarInfo(): sobrescribe (@Override) el metodo del padre. Agrega el tipo ("Revista") y el mes de publicacion al texto retornado.

R5 — Menu de consola con estructuras de control IL 1.2

La clase Main debe presentar un menu de consola que se repita hasta que el usuario elija salir. Usa un bucle while y switch para controlar las opciones:

=== BIBLIOTECA MUNICIPAL ===
1. Registrar material
2. Listar catalogo
3. Buscar material por titulo
4. Prestar material
5. Resumen del catalogo
6. Salir
Seleccione una opcion: _

Las opciones invalidas deben mostrar un mensaje y volver al menu sin que el programa se detenga.

R6 — Registrar material (con submenu) IL 1.2 IL 1.6

Al seleccionar "Registrar material", el sistema muestra un submenu para elegir entre Libro y Revista. Luego solicita los datos correspondientes y agrega el material a una coleccion ArrayList<Material>.

  • Para libros, se solicita el numero de paginas como un valor entero positivo.
  • Para revistas, se solicita el mes de publicacion como texto.
  • La cantidad disponible debe ser un numero entero positivo.

R7 — Listar catalogo (polimorfismo en accion) IL 1.5 IL 1.6

Recorre la coleccion ArrayList<Material> e imprime la informacion de cada material usando mostrarInfo().

Cada material se muestra con su formato propio (libro o revista) sin necesidad de hacer instanceof. Esto es polimorfismo: el mismo metodo produce resultados distintos segun el tipo real del objeto.

Si la lista esta vacia, mostrar un mensaje indicando que no hay materiales registrados.

R8 — Buscar material por titulo IL 1.2 IL 1.6

El usuario ingresa un texto y el sistema busca materiales cuyo titulo contenga ese texto (busqueda parcial, sin distinguir mayusculas/minusculas). Muestra todos los resultados encontrados o un mensaje si no hay coincidencias.

R9 — Prestar material (descontar disponibilidad) IL 1.2 IL 1.5 IL 1.6

El sistema lista los materiales con su indice. El usuario selecciona un material para prestar. El sistema valida:

  • Que el numero de material sea valido (exista en la lista).
  • Que la cantidad disponible sea mayor a 0.

Si el prestamo es valido, descuenta 1 unidad de cantidadDisponible y muestra un comprobante con el titulo del material, los dias de prestamo asignados (calculados con calcularDiasPrestamo()) y los ejemplares restantes.

R10 — Resumen del catalogo IL 1.2 IL 1.5 IL 1.6

Muestra un resumen que incluya:

  • Total de materiales registrados.
  • Cantidad de libros y cantidad de revistas (usa instanceof).
  • Total de ejemplares disponibles: la suma de cantidadDisponible de todos los materiales.

R11 — Manejo de excepciones IL 1.5

Toda entrada numerica del usuario debe estar protegida con try-catch. El programa nunca debe detenerse por un error de ingreso. Situaciones que deben manejarse:

  • El usuario escribe texto cuando se espera un numero (cantidad disponible, numero de paginas, indice de material).
  • El usuario ingresa un indice fuera de rango al prestar.
  • El usuario intenta prestar un material con 0 ejemplares disponibles.
  • El usuario ingresa una opcion de menu que no existe.

En cada caso, muestra un mensaje claro al usuario y vuelve al menu sin interrumpir la ejecucion.
