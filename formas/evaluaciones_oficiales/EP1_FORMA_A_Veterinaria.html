Condiciones de la evaluacion

Del entorno y la entrega

  • La evaluacion es de caracter individual. No esta permitida ninguna forma de colaboracion entre estudiantes.
  • No se permite el acceso a internet ni el uso de telefonos, relojes inteligentes ni ningun otro dispositivo externo.
  • El programa debe compilar y ejecutarse correctamente. Una solucion que no compile no permite evidenciar ningun indicador de logro.
  • El proyecto debe entregarse comprimido en formato ZIP, con tu nombre completo como nombre del archivo, en la actividad habilitada en AVA antes de que finalice la sesion.
  • No se aceptan entregas por ningun otro medio ni fuera del horario establecido. La ausencia de entrega en AVA genera automaticamente la nota minima.

De tu solucion

  • El codigo debe organizarse en clases separadas, respetando las convenciones de nomenclatura de Java: PascalCase para nombres de clase, camelCase para metodos y atributos.
  • Puedes crear metodos o clases auxiliares siempre que no contradigan los requerimientos del caso.
  • No se admite el uso de herramientas de inteligencia artificial ni de recursos digitales externos.
  • Cualquier indicio de colaboracion no autorizada, uso de IA o plagio implica la anulacion inmediata de la evaluacion con nota minima de 1.0.

Caso de negocio

Una clinica veterinaria necesita un sistema de consola en Java para gestionar el registro de mascotas y sus consultas medicas. La clinica atiende dos tipos de mascotas: mascotas domesticas (perros, gatos) y mascotas exoticas (reptiles, aves, entre otros). Ambas comparten datos generales como nombre y especie, pero se diferencian en sus atributos especificos y en la forma de calcular el costo de una consulta.

El sistema debe permitir registrar mascotas, listar las mascotas registradas, buscar mascotas por nombre, registrar consultas medicas y ver un resumen de los pacientes. Todas las entradas del usuario deben estar protegidas contra errores de ingreso.

Estructura de clases

El siguiente diagrama muestra la jerarquia de clases a implementar. La clase Mascota es abstracta y define la estructura base. Las clases MascotaDomestica y MascotaExotica heredan de ella y sobrescriben el calculo del costo de consulta.

Nota: Los costos se manejan como int (pesos chilenos enteros, sin decimales). El atributo consultasRealizadas se inicializa en 0 dentro del constructor y no se recibe como parametro. Se incrementa cada vez que se registra una consulta para esa mascota.

Requerimientos funcionales

A continuacion se detalla cada requerimiento. Las etiquetas IL indican que indicador de logro se evalua en cada parte.

R1 — Comentarios de paradigma IL 1.1

Al inicio de la clase Main.java, incluye un bloque de comentarios que explique:

  • Que paradigma de programacion se esta usando y sus caracteristicas principales.
  • Al menos 2 diferencias concretas entre el paradigma orientado a objetos (Java) y el paradigma que usabas antes (Python funcional). Por ejemplo: tipado, estructura del programa, compilacion vs. interpretacion, o forma de organizar el codigo.

R2 — Clase abstracta Mascota IL 1.3 IL 1.4

Implementa la clase abstracta Mascota segun el diagrama UML:

  • Atributos privados: nombre (String), especie (String), consultasRealizadas (int).
  • Constructor que reciba nombre y especie. El atributo consultasRealizadas se inicializa en 0.
  • Getters para los tres atributos y setter para consultasRealizadas.
  • Metodo abstracto calcularCostoConsulta() que retorna int.
  • Metodo mostrarInfo() que retorna un String con el nombre, especie, costo de consulta y cantidad de consultas realizadas. Este metodo puede ser sobrescrito por las clases hijas para agregar informacion adicional.

R3 — Clase MascotaDomestica IL 1.3 IL 1.4

Hereda de Mascota. Representa una mascota domestica (perro, gato, etc.).

  • Atributo privado adicional: vacunasAlDia (boolean).
  • Constructor que reciba los 3 parametros (2 del padre + vacunasAlDia). Usa super().
  • Getter para vacunasAlDia.
  • calcularCostoConsulta(): si vacunasAlDia es true, retorna 15000. Si es false, retorna 20000 (recargo por actualizacion de vacunas).
  • mostrarInfo(): sobrescribe (@Override) el metodo del padre. Agrega el tipo ("Domestica") y el estado de vacunas al texto retornado.

R4 — Clase MascotaExotica IL 1.3 IL 1.4

Hereda de Mascota. Representa una mascota exotica (reptil, ave, etc.).

  • Atributo privado adicional: costoPermiso (int, costo del permiso SAG requerido para la atencion).
  • Constructor que reciba los 3 parametros (2 del padre + costoPermiso). Usa super().
  • Getter para costoPermiso.
  • calcularCostoConsulta(): retorna 15000 + costoPermiso.
  • mostrarInfo(): sobrescribe (@Override) el metodo del padre. Agrega el tipo ("Exotica") y el costo del permiso al texto retornado.

R6 — Registrar mascota (con submenu) IL 1.2 IL 1.6

Al seleccionar "Registrar mascota", el sistema muestra un submenu para elegir entre Domestica y Exotica. Luego solicita los datos correspondientes y agrega la mascota a una coleccion ArrayList<Mascota>.

  • Para mascotas domesticas, se solicita si las vacunas estan al dia. El usuario ingresa "si" o "no" y se almacena como boolean.
  • Para mascotas exoticas, se solicita el costo del permiso SAG como un valor entero.

R7 — Listar mascotas (polimorfismo en accion) IL 1.5 IL 1.6

Recorre la coleccion ArrayList<Mascota> e imprime la informacion de cada mascota usando mostrarInfo().

Cada mascota se muestra con su formato propio (domestica o exotica) sin necesidad de hacer instanceof. Esto es polimorfismo: el mismo metodo produce resultados distintos segun el tipo real del objeto.

Si la lista esta vacia, mostrar un mensaje indicando que no hay mascotas registradas.

R8 — Buscar mascota por nombre IL 1.2 IL 1.6

El usuario ingresa un texto y el sistema busca mascotas cuyo nombre contenga ese texto (busqueda parcial, sin distinguir mayusculas/minusculas). Muestra todos los resultados encontrados o un mensaje si no hay coincidencias.

R9 — Registrar consulta IL 1.2 IL 1.5 IL 1.6

El sistema lista las mascotas con su indice. El usuario selecciona una mascota e ingresa una descripcion del procedimiento realizado. El sistema valida:

  • Que el numero de mascota sea valido (exista en la lista).
  • Que la descripcion no este vacia.

Si la consulta es valida, incrementa el contador consultasRealizadas de la mascota y muestra un recibo con el nombre de la mascota, el procedimiento descrito, el costo de la consulta (calculado con calcularCostoConsulta()) y el total de consultas acumuladas.

R10 — Resumen de pacientes IL 1.2 IL 1.5 IL 1.6

Muestra un resumen que incluya:

  • Total de mascotas registradas.
  • Cantidad de mascotas domesticas y cantidad de mascotas exoticas (usa instanceof).
  • Total de consultas realizadas (suma de consultasRealizadas de todas las mascotas).
  • Ingresos totales: la suma de calcularCostoConsulta() * consultasRealizadas de cada mascota.

R11 — Manejo de excepciones IL 1.5

Toda entrada numerica del usuario debe estar protegida con try-catch. El programa nunca debe detenerse por un error de ingreso. Situaciones que deben manejarse:

  • El usuario escribe texto cuando se espera un numero (costo de permiso, indice de mascota).
  • El usuario ingresa un indice fuera de rango al registrar una consulta.
  • El usuario ingresa una opcion de menu que no existe.

En cada caso, muestra un mensaje claro al usuario y vuelve al menu sin interrumpir la ejecucion.
