Condiciones de la evaluacion

Del entorno y la entrega

  • La evaluacion es de caracter individual. No esta permitida ninguna forma de colaboracion entre estudiantes.
  • No se permite el acceso a internet ni el uso de telefonos, relojes inteligentes ni ningun otro dispositivo externo.
  • El programa debe compilar y ejecutarse correctamente. Una solucion que no compile no permite evidenciar ningun indicador de logro.
  • El proyecto debe entregarse comprimido en formato ZIP, con tu nombre completo como nombre del archivo, en la actividad habilitada en AVA antes de que finalice la sesion.
  • No se aceptan entregas por ningun otro medio ni fuera del horario establecido. La ausencia de entrega en AVA genera automaticamente la nota minima.

De tu solucion

  • El codigo debe organizarse en clases separadas, respetando las convenciones de nomenclatura de Java: PascalCase para nombres de clase, camelCase para metodos y atributos.
  • Puedes crear metodos o clases auxiliares siempre que no contradigan los requerimientos del caso.
  • No se admite el uso de herramientas de inteligencia artificial ni de recursos digitales externos.
  • Cualquier indicio de colaboracion no autorizada, uso de IA o plagio implica la anulacion inmediata de la evaluacion con nota minima de 1.0.

Caso de negocio

Un taller mecanico necesita un sistema de consola en Java para gestionar las revisiones tecnicas de vehiculos. El taller atiende dos tipos de vehiculos: vehiculos particulares (automoviles de pasajeros) y vehiculos de carga (camiones, furgones). Ambos comparten datos generales como patente, marca y numero de revisiones pendientes, pero se diferencian en sus atributos especificos y en la forma de calcular el costo de cada revision.

El sistema debe permitir registrar vehiculos, listar los vehiculos registrados, buscar vehiculos por patente, realizar revisiones y ver un resumen general. Todas las entradas del usuario deben estar protegidas contra errores de ingreso.

Requerimientos funcionales

A continuacion se detalla cada requerimiento. Las etiquetas IL indican que indicador de logro se evalua en cada parte.

R1 — Comentarios de paradigma IL 1.1

Al inicio de la clase Main.java, incluye un bloque de comentarios que explique:

  • Que paradigma de programacion se esta usando y sus caracteristicas principales.
  • Al menos 2 diferencias concretas entre el paradigma orientado a objetos (Java) y el paradigma que usabas antes (Python funcional). Por ejemplo: tipado, estructura del programa, compilacion vs. interpretacion, o forma de organizar el codigo.

R2 — Clase abstracta Vehiculo IL 1.3 IL 1.4

Implementa la clase abstracta Vehiculo segun el diagrama UML:

  • Atributos privados: patente (String), marca (String), revisionesPendientes (int).
  • Constructor que reciba los 3 atributos.
  • Getters para los tres atributos y setter para revisionesPendientes.
  • Metodo abstracto calcularCostoRevision() que retorna int.
  • Metodo mostrarInfo() que retorna un String con la patente, marca, costo de revision y revisiones pendientes. Este metodo puede ser sobrescrito por las clases hijas para agregar informacion adicional.

R3 — Clase VehiculoParticular IL 1.3 IL 1.4

Hereda de Vehiculo. Representa un automovil de pasajeros.

  • Atributo privado adicional: numPasajeros (int).
  • Constructor que reciba los 4 parametros (3 del padre + numPasajeros). Usa super().
  • Getter para numPasajeros.
  • calcularCostoRevision(): retorna 30000 + (numPasajeros * 2000).
  • mostrarInfo(): sobrescribe (@Override) el metodo del padre. Agrega el tipo ("Particular") y el numero de pasajeros al texto retornado.

R4 — Clase VehiculoCarga IL 1.3 IL 1.4

Hereda de Vehiculo. Representa un vehiculo de carga (camion, furgon).

  • Atributo privado adicional: pesoMaxCarga (int, en kilogramos).
  • Constructor que reciba los 4 parametros (3 del padre + pesoMaxCarga). Usa super().
  • Getter para pesoMaxCarga.
  • calcularCostoRevision(): retorna 30000 + (pesoMaxCarga * 5).
  • mostrarInfo(): sobrescribe (@Override) el metodo del padre. Agrega el tipo ("Carga") y el peso maximo de carga al texto retornado.

La clase Main debe presentar un menu de consola que se repita hasta que el usuario elija salir. Usa un bucle while y switch para controlar las opciones:

Las opciones invalidas deben mostrar un mensaje y volver al menu sin que el programa se detenga.

R6 — Registrar vehiculo (con submenu) IL 1.2 IL 1.6

Al seleccionar "Registrar vehiculo", el sistema muestra un submenu para elegir entre Particular y Carga. Luego solicita los datos correspondientes y agrega el vehiculo a una coleccion ArrayList<Vehiculo>.

  • Para vehiculos particulares, se solicita el numero de pasajeros como un valor entero positivo.
  • Para vehiculos de carga, se solicita el peso maximo de carga en kilogramos como un valor entero positivo.
  • Las revisiones pendientes deben ser un numero entero mayor o igual a 0.

R7 — Listar vehiculos (polimorfismo en accion) IL 1.5 IL 1.6

Recorre la coleccion ArrayList<Vehiculo> e imprime la informacion de cada vehiculo usando mostrarInfo().

Cada vehiculo se muestra con su formato propio (particular o carga) sin necesidad de hacer instanceof. Esto es polimorfismo: el mismo metodo produce resultados distintos segun el tipo real del objeto.

Si la lista esta vacia, mostrar un mensaje indicando que no hay vehiculos registrados.

R8 — Buscar vehiculo por patente IL 1.2 IL 1.6

El usuario ingresa un texto y el sistema busca vehiculos cuya patente contenga ese texto (busqueda parcial, sin distinguir mayusculas/minusculas). Muestra todos los resultados encontrados o un mensaje si no hay coincidencias.

R9 — Realizar revision (descontar pendientes) IL 1.2 IL 1.5 IL 1.6

El sistema lista los vehiculos con su indice. El usuario selecciona un vehiculo para realizar su revision. El sistema valida:

  • Que el numero de vehiculo sea valido (exista en la lista).
  • Que el vehiculo tenga al menos 1 revision pendiente.

Si la revision es valida, descuenta 1 unidad de revisionesPendientes y muestra un comprobante con la patente, la marca, el costo de la revision (calculado con calcularCostoRevision()) y las revisiones pendientes restantes.

R10 — Resumen de vehiculos IL 1.2 IL 1.5 IL 1.6

Muestra un resumen que incluya:

  • Total de vehiculos registrados.
  • Cantidad de vehiculos particulares y cantidad de vehiculos de carga (usa instanceof).
  • Ingresos proyectados: la suma de calcularCostoRevision() * revisionesPendientes de cada vehiculo (lo que se facturaria si se completaran todas las revisiones pendientes).

R11 — Manejo de excepciones IL 1.5

Toda entrada numerica del usuario debe estar protegida con try-catch. El programa nunca debe detenerse por un error de ingreso. Situaciones que deben manejarse:

  • El usuario escribe texto cuando se espera un numero (revisiones pendientes, numero de pasajeros, peso de carga, indice de vehiculo).
  • El usuario ingresa un indice fuera de rango al realizar una revision.
  • El usuario intenta realizar una revision en un vehiculo con 0 revisiones pendientes.
  • El usuario ingresa una opcion de menu que no existe.

En cada caso, muestra un mensaje claro al usuario y vuelve al menu sin interrumpir la ejecucion.
